[Heading 2] ความเป็นมาและความสำคัญของปัญหา
[Normal] ปัจจุบันเทคโนโลยีสารสนเทศและระบบฐานข้อมูลมีบทบาทสำคัญต่อการจัดเก็บ ประมวลผล และบริหารจัดการข้อมูลในองค์กรและหน่วยงานต่างๆ โดยเฉพาะการใช้ระบบจัดการฐานข้อมูลร่วมกับภาษา SQL ซึ่งเป็นเครื่องมือสำคัญสำหรับการสร้างตาราง การเพิ่ม แก้ไข ลบ และสืบค้นข้อมูล (กิตติ ภักดีวัฒนะกุล, 2561) อย่างไรก็ตาม จากการจัดการเรียนการสอนเกี่ยวกับการจัดการฐานข้อมูลและภาษา SQL พบว่าผู้เรียนบางส่วนยังมีความเข้าใจเกี่ยวกับหลักการทำงานและโครงสร้างคำสั่งไม่เพียงพอ รวมถึงประสบปัญหาในการจดจำรูปแบบคำสั่ง การเลือกใช้คำสั่ง และการแก้ไขข้อผิดพลาด ส่งผลให้การเรียนรู้และการฝึกปฏิบัติเป็นไปอย่างล่าช้า ประกอบกับการสอบถามข้อสงสัยจากผู้สอนอาจไม่สามารถทำได้ทันทีในทุกช่วงเวลา ซึ่งเป็นอุปสรรคต่อการเรียนรู้ที่ต้องการความต่อเนื่อง
[Normal] จากปัญหาดังกล่าว จึงมีแนวคิดในการนำเทคโนโลยีปัญญาประดิษฐ์ (Artificial Intelligence: AI) มาประยุกต์ใช้ในการพัฒนาแชทบอท (Chatbot) เพื่อตอบคำถามเกี่ยวกับการจัดการฐานข้อมูลและภาษา SQL ซึ่งสอดคล้องกับงานวิจัยของ สุทิเทพ ศิริพิพัฒนกุล และคณะ (2567) ที่ระบุว่าเทคโนโลยีแชทบอทอัจฉริยะ (Smart Chatbot) มีความสามารถขั้นสูงในการโต้ตอบการสนทนา การตอบคำถาม และการเขียนโปรแกรมภาษาคอมพิวเตอร์ ซึ่งสามารถนำมาประยุกต์ใช้เป็นผู้ช่วยในการจัดการเรียนรู้ของผู้เรียนได้อย่างมีประสิทธิภาพ นอกจากนี้ การนำแชทบอทมาใช้ยังสามารถช่วยเสริมศักยภาพการเรียนรู้ออนไลน์และส่งเสริมกระบวนการคิดอย่างเป็นระบบของผู้เรียนให้ดียิ่งขึ้น (ศิรัฐ อิ่มแช่ม, 2562)
[Normal] ด้วยเหตุนี้ แชทบอทในงานวิจัยนี้จะทำหน้าที่เสมือนผู้ช่วยในการเรียนรู้ ที่ผู้เรียนสามารถสนทนาและสอบถามข้อสงสัยเกี่ยวกับเนื้อหา เช่น หลักการจัดการฐานข้อมูล โครงสร้างคำสั่ง SQL การใช้คำสั่ง SELECT, INSERT, UPDATE และ DELETE รวมถึงแนวทางการตรวจสอบและแก้ไขข้อผิดพลาด โดยระบบจะให้คำตอบและคำอธิบายในรูปแบบที่เข้าใจง่าย
[Normal] การพัฒนาแชทบอท AI ดังกล่าว คาดว่าจะช่วยส่งเสริมการเรียนรู้เกี่ยวกับการจัดการฐานข้อมูลและภาษา SQL ให้มีประสิทธิภาพมากยิ่งขึ้น ผู้เรียนสามารถใช้ระบบเป็นแหล่งค้นหาคำตอบและทบทวนเนื้อหาได้อย่างรวดเร็ว ช่วยลดข้อจำกัดด้านเวลาและการเข้าถึงผู้สอน ทำให้สามารถเรียนรู้ด้วยตนเองได้อย่างต่อเนื่อง นอกจากนี้ ผลจากการพัฒนาระบบยังสามารถเป็นต้นแบบในการนำเทคโนโลยี AI มาประยุกต์ใช้เพื่อสนับสนุนการเรียนการสอนด้านเทคโนโลยีสารสนเทศในรายวิชาอื่น ต่อไปได้

[Heading 2] ความรู้เบื้องต้นเกี่ยวกับข้อมูลและระบบแฟ้มข้อมูล (Data and File System)
[Normal] แชทบอทที่พัฒนาขึ้นต้องจัดเก็บและค้นหาความรู้จากตำราจำนวนมาก และเกิดข้อมูลใหม่
[Normal] ทุกครั้งที่ผู้ใช้สนทนา ทั้งข้อความคำถาม คำตอบที่ส่งกลับ และประวัติแชตการเข้าใจความหมายของข้อมูลและวิธีจัดเก็บข้อมูลจึงเป็นทั้งเนื้อหาที่แชทบอทต้องตอบ และพื้นฐานสำคัญของการออกแบบการจัดเก็บความรู้
[Heading 3] ข้อมูล สารสนเทศ และความรู้
[ภาพ] ข้อมูล (Data) หมายถึง ข้อเท็จจริงดิบที่ยังไม่ผ่านการประมวลผลและยังไม่สื่อความหมาย สารสนเทศ (Information) คือข้อมูลที่ผ่านการประมวลผล คำนวณ และวิเคราะห์แล้วจนนำไปใช้ประโยชน์ได้ ส่วนความรู้ (Knowledge) เป็นรูปแบบหรือแนวโน้มที่สกัดได้จากสารสนเทศจำนวนมาก ตำราระบุว่าสารสนเทศที่ดีควรมีคุณสมบัติ 4 ประการ คือ ถูกต้อง รวดเร็วและเป็นปัจจุบัน มีความสมบูรณ์ ชัดเจนกระชับ และสอดคล้องกับความต้องการของผู้ใช้ ดังตัวอย่างในภาพที่ 2.1
[Heading 8] ความสัมพันธ์ของข้อมูล สารสนเทศ และความรู้ในระบบแชทบอท 
[Heading 3] ชนิดของข้อมูลและโครงสร้างแฟ้มข้อมูล
[Normal] ชนิดของข้อมูลแบ่งเป็น 5 ชนิด ได้แก่ ข้อความ ตัวเลข วันที่และเวลา รูปภาพ และเสียง 
การกำหนดชนิดข้อมูลก่อนจัดเก็บมีผลต่อพื้นที่จัดเก็บและการเขียนโปรแกรมในภายหลังในระบบ
แชทบอท ข้อความสนทนาเป็นข้อมูลชนิดข้อความ เวลาที่ส่งข้อความเป็นข้อมูลชนิดวันที่และเวลา ส่วนภาพและแผนภาพในตำราเป็นข้อมูลชนิดรูปภาพ ซึ่งยังไม่ได้ถูกแปลงเข้าฐานความรู้ของระบบ
[Normal] โครงสร้างของแฟ้มข้อมูลเรียงจากหน่วยใหญ่ไปหน่วยเล็ก คือ แฟ้มข้อมูล (File) เรคอร์ด (Record) ฟิลด์ (Field) ไบต์ (Byte) และบิต (Bit) (ฐาปนี, 2562, หน้า 6-7) นอกจากนี้ แฟ้มข้อมูลยังแบ่งตามลักษณะการใช้งานเป็น 4 ประเภท ดังตารางที่ 2-1 โดยตัวอย่างในคอลัมน์สุดท้ายเป็นการประยุกต์ของผู้จัดทำ
[Heading 9] ประเภทของแฟ้มข้อมูลและตัวอย่างในระบบแชทบอท
[Heading 3] ระบบแฟ้มข้อมูลและข้อจำกัด
[Normal] ระบบแฟ้มข้อมูลเป็นการที่แต่ละหน่วยงานหรือแต่ละโปรแกรมเก็บแฟ้มข้อมูลแยกกัน มีข้อดีคือประมวลผลได้รวดเร็วและต้นทุนเริ่มต้นต่ำ แต่มีข้อจำกัดสำคัญ 3 ประการ (ฐาปนี, 2562, หน้า 9-14) ดังนี้
[Heading 4] ข้อมูลถูกเก็บแยกจากกันทำให้รวบรวมข้อมูลได้ช้าและข้อมูลอาจไม่เป็นปัจจุบัน
[Heading 4] ข้อมูลซ้ำซ้อนซึ่งนำไปสู่ความผิดพลาดจากการเพิ่มข้อมูล (Insert Anomaly) การลบข้อมูล (Deletion Anomaly) และการเปลี่ยนแปลงข้อมูล (Modification Anomaly)
[Heading 4] ข้อมูลขึ้นต่อโครงสร้างของโปรแกรม (Data Dependence) ทำให้การแก้ไขโครงสร้างข้อมูลต้องแก้ไขโปรแกรมที่เกี่ยวข้องทั้งหมดด้วย
[Normal] วิธีฐานข้อมูล (Database Approach) แก้ปัญหาเหล่านี้ด้วยการรวบรวมข้อมูลที่สัมพันธ์กันไว้ที่ศูนย์กลางในรูปแบบตาราง ผู้ใช้หลายคนใช้ข้อมูลชุดเดียวกันได้ และข้อมูลเป็นอิสระจากโปรแกรม (ฐาปนี, 2562, หน้า 15-16) ดังภาพที่ 2-2 ปัจจุบัน Ch-Bot เก็บความรู้ทั้งหมดไว้ในไฟล์ Markdownไฟล์เดียวพร้อมไฟล์ manifest สำหรับตรวจสอบ ส่วนประวัติแชตบนหน้าเว็บเก็บไว้ใน localStorage ของเบราว์เซอร์ (และเป็นไฟล์ JSON ในช่องทางเสริม) ซึ่งเหมาะกับขนาดข้อมูลในปัจจุบัน แต่ localStorage ไม่ใช่การสำรองข้อมูลถาวรและไม่ซิงก์ข้ามเครื่อง หากต้องการให้ประวัติแชตคงอยู่ถาวรหรือมีข้อมูลเพิ่มขึ้นมาก การย้ายไปจัดเก็บด้วยวิธีฐานข้อมูลจะช่วยลดความซ้ำซ้อนและควบคุมข้อมูลได้ดีกว่า
[Heading 8] เปรียบเทียบระบบแฟ้มข้อมูลกับระบบฐานข้อมูล 
[Heading 2] ระบบฐานข้อมูล (Database System)
[Heading 3] ความหมายและแนวคิดของระบบฐานข้อมูล
[Normal] ระบบฐานข้อมูล (Database System) คือการรวบรวมข้อมูลหรือแฟ้มข้อมูลที่เกี่ยวข้องกันไว้ในที่เดียวอย่างเป็นระบบ เพื่อให้หลายหน่วยงานหรือหลายผู้ใช้เรียกใช้ร่วมกันได้ ข้อมูลถูกจัดเก็บในรูปตารางหลายตารางที่มีความสัมพันธ์กัน ทำให้ข้อมูลไม่ซ้ำซ้อน มีความเป็นอิสระของข้อมูล และควบคุมได้จากศูนย์กลาง (ฐาปนี, 2562, หน้า 21-23)
[Heading 3]  ระบบจัดการฐานข้อมูล (Database Management System: DBMS)
[Normal] DBMS เป็นซอฟต์แวร์ที่ทำหน้าที่เป็นตัวกลางระหว่างผู้ใช้หรือโปรแกรมประยุกต์กับฐานข้อมูล ควบคุมการจัดเก็บ บริหารจัดการ และบำรุงรักษาข้อมูล ให้ผู้ใช้หลายคนเพิ่ม ลบ แก้ไขข้อมูลพร้อมกันได้โดยไม่กระทบกัน โต้ตอบกับข้อมูลด้วยภาษา SQL รักษาความมั่นคงปลอดภัยของข้อมูล และมีระบบสำรองและกู้คืนข้อมูลในกรณีฉุกเฉิน (ฐาปนี, 2562, หน้า 24-25) ตัวอย่างระบบจัดการฐานข้อมูลที่ตำรากล่าวถึง ได้แก่ SQL Server, Microsoft Access และ MySQL (ฐาปนี, 2562, หน้า 6)
[Heading 3] ส่วนประกอบด้านสภาพแวดล้อมของระบบฐานข้อมูล
[Normal] ส่วนประกอบด้านสภาพแวดล้อมของระบบฐานข้อมูลมี 5 ส่วน ดังตารางที่ 2-2
[Heading 9] ส่วนประกอบด้านสภาพแวดล้อมของระบบฐานข้อมูล
[Heading 3] ข้อดีและข้อเสียของวิธีฐานข้อมูล
[Normal] ข้อดีของวิธีฐานข้อมูล ได้แก่ ความเป็นอิสระของโปรแกรมและข้อมูล การลดความซ้ำซ้อนของข้อมูล ข้อมูลสอดคล้องตรงกัน และเข้าถึงข้อมูลได้รวดเร็ว ส่วนข้อเสีย ได้แก่ ระบบมีความซับซ้อน ต้องใช้พื้นที่จัดเก็บขนาดใหญ่ มีต้นทุนสูง และหากระบบเกิดความเสียหายจะส่งผลกระทบกว้าง (ฐาปนี, 2562, หน้า 28-30)
[Heading 3] ประเภทการประยุกต์ใช้งานฐานข้อมูล
[Normal] การประยุกต์ใช้งานฐานข้อมูลแบ่งตามขนาดของการใช้งานได้ 4 ประเภท คือ ฐานข้อมูลส่วนบุคคล ฐานข้อมูลระดับแผนก ฐานข้อมูลระดับเอ็นเตอร์ไพรส์ และฐานข้อมูลอินเทอร์เน็ต (ฐาปนี, 2562, หน้า 31-32) แชทบอทที่ให้บริการผ่านเว็บไซต์จัดอยู่ในกลุ่มฐานข้อมูลอินเทอร์เน็ต ซึ่งต้องรองรับผู้ใช้หลายคนพร้อมกันและควบคุมสิทธิ์การเข้าถึงของผู้ใช้แต่ละกลุ่มได้
[Heading 2] สถาปัตยกรรมระบบฐานข้อมูล 3 ระดับ (Three-Level Database Architecture)
[Heading 3] แนวคิดและสถาปัตยกรรม 3 ระดับ
[Normal] สถาปัตยกรรมระบบฐานข้อมูลอธิบายภาพการมองข้อมูลในแต่ละชั้นของระบบ โดยแต่ละชั้นทำงานเป็นอิสระต่อกันแต่ส่งต่อข้อมูลระหว่างชั้นได้ สถาปัตยกรรมที่นิยมใช้คือแบบ 3 ระดับตามที่ ANSI/SPARC กำหนด (ฐาปนี, 2562, หน้า 37-40) ประกอบด้วย ดังภาพที่ 2-3
[Heading 4] ระดับภายนอก (External Level) คือมุมมองของผู้ใช้แต่ละกลุ่ม ผู้ใช้เห็นเฉพาะข้อมูลที่จำเป็นต่อการใช้งาน 
[Heading 4] ระดับแนวคิด (Conceptual Level) คือโครงสร้างเชิงตรรกะของข้อมูลทั้งหมดในฐานข้อมูล เน้นความสัมพันธ์ระหว่างข้อมูลหรือแบบจำลองข้อมูล
[Heading 4] ระดับภายใน (Internal Level) คือการจัดเก็บข้อมูลเชิงกายภาพ เช่น โครงสร้างแฟ้มแบบเรียงลำดับหรือแบบดัชนี ซึ่งส่งผลต่อความเร็วในการเข้าถึงข้อมูล (ฐาปนี, 2562, หน้า 45)
[Heading 8] สถาปัตยกรรมฐานข้อมูล 3 ระดับ 
[Heading 3] ความเป็นอิสระของข้อมูลและการแปลงรูป
[Normal] ความเป็นอิสระของข้อมูล (Data Independence) หมายถึง การที่ระดับสถาปัตยกรรมที่สูงกว่าไม่ได้รับผลกระทบจากการเปลี่ยนแปลงในระดับที่ต่ำกว่า เช่น การเปลี่ยนวิธีจัดเก็บไฟล์หรือเพิ่มดัชนีในระดับภายในไม่ทำให้ผู้ใช้หรือโปรแกรมต้องแก้ไข ทั้งนี้ระบบจัดการฐานข้อมูลต้องทำหน้าที่แปลงรูป (Mapping) ระหว่างระดับภายนอกกับระดับแนวคิด และระหว่างระดับแนวคิดกับระดับภายใน 
[Heading 3] ประโยชน์ของสถาปัตยกรรมและโครงร่างฐานข้อมูล
[Normal] ประโยชน์ของสถาปัตยกรรม 3 ระดับ คือ ผู้ใช้ไม่ต้องสนใจรายละเอียดการจัดเก็บข้อมูล ผู้ใช้แต่ละกลุ่มมองข้อมูลชุดเดียวกันในมุมมองที่เหมาะกับตนเอง และปรับเปลี่ยนโครงสร้างได้ง่ายขึ้น โครงร่างฐานข้อมูลประกอบด้วยสกีมา (Schema) ซึ่งเป็นโครงสร้างที่ออกแบบไว้ และอินสแตนซ์ (Instance) ซึ่งเป็นข้อมูลจริง ณ เวลาใดเวลาหนึ่ง ในแชทบอทนี้ ผู้เรียนเห็นเพียงหน้าจอแชตและคำตอบที่ได้รับ โดยไม่ต้องรู้ว่าเนื้อหาถูกจัดเก็บอย่างไร ขณะที่ผู้พัฒนาดูแลไฟล์ความรู้และ manifest ได้โดยตรง ซึ่งเป็นตัวอย่างของมุมมองระดับภายนอกที่แตกต่างกันบนข้อมูลชุดเดียวกัน
[Heading 2] แบบจำลองข้อมูลเชิงสัมพันธ์และชนิดของคีย์ (Relational Model and Keys)
[Heading 3] แบบจำลองข้อมูล
[Normal] แบบจำลองข้อมูล (Data Model) คือการอธิบายโครงสร้างเชิงตรรกะของข้อมูลด้วยภาพกราฟิก ถือเป็นขั้นตอนแรกของการออกแบบฐานข้อมูล โดยกำหนดขอบเขตของข้อมูลให้ชัดเจน ประกอบด้วยเอ็นทิตี้ แอตทริบิวต์ ความสัมพันธ์ และข้อจำกัดของข้อมูล 
[Heading 3] แบบจำลองฐานข้อมูลเชิงสัมพันธ์
[Normal] แบบจำลองฐานข้อมูลเชิงสัมพันธ์ (Relational Database Model) พัฒนาขึ้นในปี ค.ศ. 1970 โดย E. F. Codd แห่งบริษัท IBM (Codd, 1970 อ้างถึงใน ฐาปนี, 2562, หน้า 57) เป็นแบบจำลองที่จัดเก็บข้อมูลเป็นตารางหลายตารางที่มีความสัมพันธ์กัน และใช้ภาษา SQL ในการเรียกดูข้อมูล ข้อดีคือผู้ใช้มองเห็นภาพรวมของข้อมูลได้ง่าย เชื่อมโยงข้อมูลได้สะดวกโดยไม่ต้องรู้ว่าข้อมูลถูกจัดเก็บจริงอย่างไร และลดความซ้ำซ้อนของข้อมูลด้วยการอ้างอิงผ่านคีย์ ส่วนข้อจำกัดคือหากออกแบบไม่ดีเมื่อข้อมูลมีจำนวนมากอาจทำให้ระบบทำงานช้า 
[Heading 3] โครงสร้างของรีเลชัน
[Normal] รีเลชัน (Relation) คือตารางสองมิติที่ประกอบด้วยแถวที่เรียกว่าทูเพิล (Tuple) และคอลัมน์ที่เรียกว่าแอตทริบิวต์ (Attribute) จำนวนแอตทริบิวต์เรียกว่าดีกรี (Degree) จำนวนทูเพิลเรียกว่าคาร์ดินัลลิตี้ (Cardinality) และขอบเขตค่าที่แอตทริบิวต์รับได้เรียกว่าโดเมน (Domain) คุณสมบัติของรีเลชันคือ ไม่มีทูเพิลที่ซ้ำกัน ลำดับของแอตทริบิวต์ไม่มีผลต่อตาราง และค่าในแต่ละช่องมีได้เพียงค่าเดียว 
[Heading 3] ชนิดของคีย์
[Normal] คีย์เป็นแอตทริบิวต์หรือกลุ่มของแอตทริบิวต์ที่ใช้ระบุความแตกต่างของข้อมูลแต่ละแถว ตำราแบ่งคีย์ออกเป็นชนิดต่าง ดังตารางที่ 2-3 โดยตัวอย่างในคอลัมน์สุดท้ายเป็นการประยุกต์ของผู้จัดทำ
[Heading 9] ชนิดของคีย์พร้อมตัวอย่างในฐานข้อมูลแชทบอท
[Heading 3] กฎความคงสภาพของข้อมูล (Data Integrity Rule)
[Normal] กฎความคงสภาพของข้อมูลเป็นข้อกำหนดที่ควบคุมความถูกต้องของตารางและป้องกันความผิดพลาดจากการลบหรือแก้ไขข้อมูล ประกอบด้วย 3 กฎ (ฐาปนี, 2562, หน้า 74-77) ดังนี้
[Heading 4] กฎความคงสภาพของเอ็นทิตี้ (Entity Integrity) คีย์หลักของตารางต้องไม่เป็นค่าว่าง (NOT NULL)
[Heading 4] กฎความคงสภาพของโดเมน (Domain Integrity) ค่าข้อมูลต้องอยู่ในช่วงที่กำหนด เช่น เกรดเฉลี่ยสะสมต้องอยู่ระหว่าง 0.00 ถึง 4.00
[Heading 4] กฎความคงสภาพของการอ้างอิง (Referential Integrity) คีย์นอกต้องอ้างอิงถึงค่าที่มีอยู่จริงในคีย์หลักของอีกรีเลชันหนึ่ง เช่น ห้ามบันทึกข้อความแชตที่อ้างอิงรหัสหัวข้อซึ่งไม่มีอยู่จริงในตารางหัวข้อ
[Heading 2] แผนภาพอีอาร์ (Entity Relationship Diagram: ER-Diagram)
[Heading 3] ความหมายและองค์ประกอบของแผนภาพอีอาร์
[Normal] แผนภาพอีอาร์หรือแบบจำลองโครงสร้างฐานข้อมูลเป็นแผนภาพเชิงแนวคิดที่แสดงเอ็นทิตี้และความสัมพันธ์ระหว่างเอ็นทิตี้ ช่วยให้นักวิเคราะห์ระบบและผู้พัฒนาระบบเข้าใจตรงกันก่อนสร้างฐานข้อมูลจริง องค์ประกอบหลักมี 3 ส่วน คือ เอ็นทิตี้ แอตทริบิวต์ และความสัมพันธ์ โดยใช้สัญลักษณ์ตามภาพที่ 2-4
[Heading 8] สัญลักษณ์ที่ใช้ในแผนภาพอีอาร์ 
[Heading 3] เอ็นทิตี้ (Entity)
[Normal] เอ็นทิตี้ คือสิ่งที่สามารถนำมาสร้างเป็นตารางในฐานข้อมูลได้ อาจเป็นบุคคล สถานที่ วัตถุ แนวคิด หรือเหตุการณ์ เอ็นทิตี้แบ่งเป็นเอ็นทิตี้แบบปกติ (Strong Entity) ซึ่งมีคีย์หลักของตนเอง และเอ็นทิตี้แบบอ่อนแอ (Weak Entity) ซึ่งต้องพึ่งพาเอ็นทิตี้อื่นและนำคีย์หลักของเอ็นทิตี้หลักมาเป็นส่วนหนึ่งของคีย์ตนเอง เช่น เอ็นทิตี้สมาชิกในครอบครัวที่ต้องอาศัยเอ็นทิตี้พนักงาน นอกจากนี้ยังมีเอ็นทิตี้แบบเรียกซ้ำ (Recursive Entity) ซึ่งมีความสัมพันธ์กับตัวเอง
[Heading 3] แอตทริบิวต์ (Attribute)
[Normal] แอตทริบิวต์คือคุณลักษณะเฉพาะของแต่ละเอ็นทิตี้ที่บอกว่าตารางนั้นเก็บข้อมูลอะไรบ้าง แบ่งเป็น 5 แบบ ได้แก่ แอตทริบิวต์ธรรมดา แอตทริบิวต์ที่เป็นคีย์ แอตทริบิวต์แบบแยกตัวประกอบ (Composite Attribute) เช่น ที่อยู่ซึ่งแบ่งเป็นบ้านเลขที่ ตำบล อำเภอ จังหวัด แอตทริบิวต์แบบหลายค่า (Multivalued Attribute) และแอตทริบิวต์ที่คำนวณได้ (Derived Attribute) เช่น อายุที่คำนวณจากวันเดือนปีเกิด
[Heading 3] ความสัมพันธ์และคาร์ดินัลลิตี้
[Normal] ความสัมพันธ์ (Relationship) เป็นหัวใจสำคัญของการออกแบบแผนภาพอีอาร์ ใช้แสดงว่าเอ็นทิตี้หนึ่งเกี่ยวข้องกับอีกเอ็นทิตี้หนึ่งอย่างไร โดยแบ่งเป็น 3 แบบ คือ หนึ่งต่อหนึ่ง (1:1) หนึ่งต่อกลุ่ม (1:N) และกลุ่มต่อกลุ่ม (M:N) การอธิบายลักษณะความสัมพันธ์เรียกว่าคาร์ดินัลลิตี้ (Cardinality) เช่น แผนกหนึ่งมีพนักงานได้หลายคนแต่พนักงานหนึ่งคนอยู่ได้เพียงแผนกเดียว จึงเป็นความสัมพันธ์แบบหนึ่งต่อกลุ่ม
[Heading 3] ตัวอย่างแผนภาพอีอาร์สำหรับจัดเก็บความรู้และประวัติแชตของแชทบอท
[Normal] ปัจจุบัน Ch-Bot เก็บความรู้ไว้ในไฟล์ Markdown ที่แปลงจากตำราตามสารบัญ รวม 172 หัวข้อ และเก็บประวัติแชตใน localStorage หรือไฟล์ JSON ผู้จัดทำจึงนำหลักการข้างต้นมาออกแบบตัวอย่างแผนภาพอีอาร์ เพื่อแสดงว่าหากย้ายข้อมูลเหล่านี้ไปจัดเก็บในฐานข้อมูลเชิงสัมพันธ์จะออกแบบได้อย่างไร ดังภาพที่ 2-5 ประกอบด้วย 5 เอ็นทิตี้ คือ บท หัวข้อ คำสำคัญ เซสชันแชต และข้อความ โดยมีความสัมพันธ์ตามตารางที่ 2-4 และใช้เป็นตัวอย่างประกอบการอธิบายในหัวข้อ 2.6 ถึง 2.12
[Heading 8] ตัวอย่างแผนภาพอีอาร์สำหรับจัดเก็บความรู้และประวัติแชตของแชทบอท 
[Heading 9] ความสัมพันธ์ระหว่างเอ็นทิตี้ในตัวอย่างฐานข้อมูลของแชทบอท
[Heading 2] การแปลง ER-Diagram เป็นรีเลชันและพจนานุกรมข้อมูล (Transforming ER-Diagram and Data Dictionary)
[Heading 3] สกีมาและรีเลชัน
[Normal] เมื่อออกแบบแผนภาพอีอาร์แล้ว ขั้นต่อไปคือการแปลงให้อยู่ในรูปของตาราง โดยสกีมา (Schema) คือคำอธิบายโครงสร้างของเอ็นทิตี้และแอตทริบิวต์ รีเลชัน (Relation) คือตารางสองมิติที่แปลงมาจากสกีมา และสกีมาเชิงสัมพันธ์ (Relation Schema) คือการระบุความสัมพันธ์ระหว่างรีเลชันผ่านคีย์ (ฐาปนี, 2562, หน้า 126-130)
[Heading 3] หลักการแปลงเอ็นทิตี้ แอตทริบิวต์ และความสัมพันธ์
[Normal] หลักการแปลงแผนภาพอีอาร์เป็นรีเลชัน (ฐาปนี, 2562, หน้า 131-157) สรุปได้ดังนี้
[Heading 4] เอ็นทิตี้แบบปกติแปลงเป็นรีเลชันที่ใช้ชื่อเดิม โดยแอตทริบิวต์เป็นคอลัมน์และกำหนดคีย์หลัก ส่วนเอ็นทิตี้แบบอ่อนแอต้องนำคีย์หลักของเอ็นทิตี้หลักมาเป็นคีย์นอกและเป็นส่วนหนึ่งของคีย์หลัก
[Heading 4] แอตทริบิวต์แบบแยกตัวประกอบแปลงเป็นคอลัมน์ย่อย ส่วนแอตทริบิวต์แบบหลายค่าต้องแยกเป็นรีเลชันใหม่
[Heading 4] ความสัมพันธ์แบบ 1:1 แปลงได้ 3 วิธี เช่น รวมสองเอ็นทิตี้เป็นรีเลชันเดียว หรือเพิ่มคีย์นอกในรีเลชันใดรีเลชันหนึ่ง
[Heading 4] ความสัมพันธ์แบบ 1:N นำคีย์หลักของฝั่ง 1 เป็นคีย์นอกในรีเลชันของฝั่ง N
[Heading 4] ความสัมพันธ์แบบ M:N ต้องสร้างรีเลชันใหม่ โดยนำคีย์หลักของทั้งสองฝั่งมาประกอบกันเป็นคีย์ประกอบ
[Heading 3] ตัวอย่างการแปลงเป็นรีเลชันสำหรับแชทบอท
[Normal] เมื่อแปลงจากภาพที่ 2-5 ตามหลักการข้างต้น จะได้สกีมาเชิงสัมพันธ์ตามตารางที่ 2-5 ซึ่งความสัมพันธ์แบบ M:N ระหว่างหัวข้อกับคำสำคัญถูกแปลงเป็นรีเลชัน topic_keywords ที่มีคีย์ประกอบ ส่วนแอตทริบิวต์ topic_id ในรีเลชัน messages กำหนดให้เป็นค่าว่างได้ในกรณีที่ไม่พบหัวข้อที่ตรงกับคำถาม ซึ่งบอทจะตอบว่าไม่มีข้อมูลเรื่องนี้ในตำรา
[Heading 9] สกีมาเชิงสัมพันธ์ที่แปลงจากแผนภาพอีอาร์
[Heading 3] พจนานุกรมข้อมูล (Data Dictionary)
[Normal] พจนานุกรมข้อมูลเป็นเอกสารที่อธิบายรายละเอียดของแต่ละตาราง ได้แก่ ชื่อฟิลด์ ชนิดข้อมูล ขนาด คีย์ และคำอธิบาย ช่วยให้ผู้พัฒนาเข้าใจโครงสร้างตรงกันและใช้เป็นเอกสารอ้างอิงเมื่อสร้างตารางด้วยภาษา SQL (ฐาปนี, 2562, หน้า 158-162) ตัวอย่างพจนานุกรมข้อมูลของตาราง messages แสดงดังตารางที่ 2-6
[Heading 9] ตัวอย่างพจนานุกรมข้อมูลของตาราง messages
[Heading 2] นอร์มัลไลเซชัน (Normalization)
[Heading 3] แนวคิดและความจำเป็น
[Normal] นอร์มัลไลเซชัน (Normalization) เป็นเทคนิคหนึ่งของการออกแบบฐานข้อมูลเชิงสัมพันธ์ ที่ตรวจสอบและปรับโครงสร้างตารางให้อยู่ในรูปแบบมาตรฐานที่เรียกว่านอร์มัลฟอร์ม เพื่อลดความซ้ำซ้อนของข้อมูลและป้องกันความผิดพลาดจากการเพิ่ม ลบ และแก้ไขข้อมูล กระบวนการนี้พัฒนาโดย Codd ในปี ค.ศ. 1972 
[Heading 3] ฟังก์ชันการขึ้นต่อกัน
[Normal] ฟังก์ชันการขึ้นต่อกัน (Functional Dependency) คือการที่ค่าของแอตทริบิวต์หนึ่งกำหนดค่าของอีกแอตทริบิวต์หนึ่ง เช่น user_id กำหนดค่า display_name ตำราแบ่งการขึ้นต่อกันที่ต้องพิจารณาในการนอร์มัลไลซ์ ได้แก่ การขึ้นต่อกันเพียงบางส่วนของคีย์หลัก (Partial Dependency) และการขึ้นต่อกันของแอตทริบิวต์ที่ไม่ใช่คีย์ (Transitive Dependency)
[Heading 3] นอร์มัลฟอร์มระดับที่ 1 ถึง 3
[Normal] กระบวนการนอร์มัลไลเซชันเริ่มจากตารางที่ยังไม่ผ่านการนอร์มัลไลซ์ แล้วปรับเป็นนอร์มัลฟอร์มระดับที่ 1 2 และ 3 ตามลำดับ ดังภาพที่ 2-6 โดยมีเกณฑ์ดังนี้
[Heading 8] ขั้นตอนการนอร์มัลไลเซชัน 
[Heading 4] นอร์มัลฟอร์มระดับที่ 1 (1NF) ข้อมูลในตารางต้องแยกเป็นแถว และทุกช่องเก็บค่าเดียว ไม่มีกลุ่มค่าซ้ำ 
[Heading 4] นอร์มัลฟอร์มระดับที่ 2 (2NF) ต้องอยู่ใน 1NF และไม่มีแอตทริบิวต์ที่ไม่ใช่คีย์ขึ้นกับคีย์หลักเพียงบางส่วน 
[Heading 4] นอร์มัลฟอร์มระดับที่ 3 (3NF) ต้องอยู่ใน 2NF และไม่มีแอตทริบิวต์ที่ไม่ใช่คีย์ขึ้นต่อกันเอง 
[Normal] นอกจากนี้ยังมีรูปแบบ BCNF ที่พัฒนาโดย R. Boyce และ E. F. Codd ซึ่งเข้มงวดกว่า 3NF รวมถึงนอร์มัลฟอร์มระดับที่ 4 และ 5 แต่ในทางปฏิบัติพบการใช้งานค่อนข้างน้อย 
[Heading 3] ตัวอย่างการนอร์มัลไลซ์ตารางของแชทบอท
[Normal] ขั้นที่ 1 (1NF) ตารางหัวข้อที่เก็บคำสำคัญหลายค่าไว้ในช่องเดียวไม่อยู่ใน 1NF จึงแยกคำสำคัญออกเป็นรีเลชันใหม่
[Normal] ก่อน: topics(topic_id, title, keywords)   -- keywords = "คีย์หลัก, primary key"
[Normal] หลัง: topics(topic_id, title)
[Normal]       topic_keywords(topic_id, keyword)
[Normal] ขั้นที่ 2 (2NF) ตารางที่มีคีย์ประกอบ (msg_id, topic_id) แต่ message_text ขึ้นกับ msg_id เพียงอย่างเดียว และ topic_title ขึ้นกับ topic_id เพียงอย่างเดียว จึงแยกตารางเพื่อตัดการขึ้นต่อกันบางส่วน
[Normal] ก่อน: message_topics(msg_id, topic_id, message_text, topic_title)
[Normal] หลัง: messages(msg_id, message_text)
[Normal]       topics(topic_id, title)
[Normal]       message_topics(msg_id, topic_id)
[Normal] ขั้นที่ 3 (3NF) ตารางหัวข้อที่มี chapter_title ขึ้นกับ chapter_id ซึ่งไม่ใช่คีย์หลัก เป็นการขึ้นต่อกันระหว่างแอตทริบิวต์ที่ไม่ใช่คีย์ จึงแยกบทออกเป็นตารางใหม่
[Normal] ก่อน: topics(topic_id, title, chapter_id, chapter_title)
[Normal] หลัง: topics(topic_id, title, chapter_id)
[Normal]       chapters(chapter_id, chapter_title)
[Heading 2] ภาษา SQL: การสร้างโครงสร้างและการจัดการข้อมูล 
[Heading 3] ความหมายและประเภทของคำสั่ง SQL
[Normal] SQL (Structured Query Language) เป็นภาษามาตรฐานสำหรับจัดเก็บ จัดการ และเรียกค้นข้อมูลในฐานข้อมูล มีรูปแบบเป็นภาษาอังกฤษที่เรียนรู้ได้ คำสั่ง SQL แบ่งเป็น 3 กลุ่ม ได้แก่ ภาษานิยามข้อมูล (DDL) ประกอบด้วยคำสั่ง CREATE ALTER และ DROP ภาษาจัดการข้อมูล (DML) ประกอบด้วยคำสั่ง INSERT UPDATE DELETE และ SELECT และภาษาควบคุมข้อมูล (DCL) ประกอบด้วยคำสั่ง GRANT และ REVOKE นอกจากนี้ยังมีรูปแบบการใช้งานสองแบบ คือ Interactive SQL ที่สั่งงานบนหน้าจอโดยตรง และ Embedded SQL ที่เขียนคำสั่งร่วมกับโปรแกรมภาษาอื่น ซึ่งเป็นรูปแบบที่โปรแกรมของแชทบอทใช้เชื่อมต่อกับฐานข้อมูลเมื่อจัดเก็บข้อมูลด้วย DBMS
[Heading 3] ชนิดข้อมูลและข้อกำหนดของคอลัมน์
[Normal] ก่อนสร้างตารางต้องกำหนดชนิดข้อมูลของแต่ละคอลัมน์ (ฐาปนี, 2562, หน้า 215-216) ตำราใช้ชนิดข้อมูลของ Microsoft Access เป็นตัวอย่าง ซึ่งเทียบได้กับชนิดข้อมูลของระบบจัดการฐานข้อมูลอื่นดังตารางที่ 2-7 (คอลัมน์สุดท้ายเป็นการเทียบเคียงโดยผู้จัดทำ) และสามารถกำหนดข้อกำหนดของคอลัมน์ได้ 5 แบบ คือ PRIMARY KEY, FOREIGN KEY, REFERENCES, NOT NULL และ UNIQUE (ฐาปนี, 2562, หน้า 217-222) ทั้งนี้ตัวอย่างคำสั่ง SQL ในตำราเป็นรูปแบบของ Microsoft Access เป็นหลัก เช่น ชนิด NUMBER และ AUTOINCREMENT จึงไม่ควรอ้างว่าใช้ได้กับทุกระบบจัดการฐานข้อมูล ตัวอย่างในบทนี้จึงปรับเป็นรูปแบบของ MySQL
[Heading 9] การเทียบชนิดข้อมูลของตำรากับชนิดข้อมูลที่ใช้ในตัวอย่าง
[Heading 3] คำสั่ง CREATE, ALTER และ DROP
[Normal] คำสั่ง CREATE ใช้สร้างฐานข้อมูลและตาราง คำสั่ง ALTER ใช้เพิ่ม ลบ หรือปรับเปลี่ยนคอลัมน์ในตาราง และคำสั่ง DROP ใช้ลบตาราง (ฐาปนี, 2562, หน้า 217-224) ตัวอย่างการสร้างตาราง chapters, topics และ messages สำหรับจัดเก็บความรู้และประวัติแชตเป็นดังนี้
[Normal] CREATE DATABASE ch_bot_db;
[Normal] CREATE TABLE chapters (
[Normal]   chapter_id    INT AUTO_INCREMENT PRIMARY KEY,
[Normal]   chapter_no    INT NOT NULL UNIQUE,
[Normal]   chapter_title VARCHAR(200) NOT NULL
[Normal] );
[Normal] CREATE TABLE topics (
[Normal]   topic_id   INT AUTO_INCREMENT PRIMARY KEY,
[Normal]   chapter_id INT NOT NULL,
[Normal]   section_no VARCHAR(10) NOT NULL,
[Normal]   title      VARCHAR(255) NOT NULL,
[Normal]   content    TEXT NOT NULL,
[Normal]   FOREIGN KEY (chapter_id) REFERENCES chapters(chapter_id)
[Normal] );
[Normal] CREATE TABLE messages (
[Normal]   msg_id       INT AUTO_INCREMENT PRIMARY KEY,
[Normal]   session_id   INT NOT NULL,
[Normal]   topic_id     INT NULL,
[Normal]   sender_type  VARCHAR(10) NOT NULL,
[Normal]   message_text TEXT NOT NULL,
[Normal]   sent_at      DATETIME NOT NULL,
[Normal]   FOREIGN KEY (session_id) REFERENCES chat_sessions(session_id),
[Normal]   FOREIGN KEY (topic_id)   REFERENCES topics(topic_id)
[Normal] );
[Normal] ALTER TABLE topics ADD COLUMN char_count INT;
[Normal] DROP TABLE temp_messages;
[Heading 3] คำสั่ง INSERT, UPDATE และ DELETE
[Normal] คำสั่ง INSERT INTO ใช้เพิ่มแถวข้อมูลใหม่ โดยระบุคอลัมน์หรือไม่ระบุคอลัมน์ก็ได้ คำสั่ง UPDATE ใช้แก้ไขข้อมูลที่บันทึกไว้แล้ว และคำสั่ง DELETE ใช้ลบข้อมูลแถวที่ต้องการ ทั้งสองคำสั่งหลังควรระบุเงื่อนไข WHERE เสมอ เพื่อไม่ให้กระทบข้อมูลทุกแถวในตาราง  ตัวอย่างเป็นดังนี้
[Normal] INSERT INTO chapters (chapter_id, chapter_no, chapter_title)
[Normal] VALUES (4, 4, 'แบบจำลองฐานข้อมูลเชิงสัมพันธ์');
[Normal] UPDATE topics
[Normal] SET title = 'ประเภทของคีย์'
[Normal] WHERE section_no = '4.5';
[Normal] DELETE FROM messages
[Normal] WHERE msg_id = 1001;
[Heading 2] ภาษา SQL: การเลือกข้อมูลด้วยคำสั่ง SELECT
[Heading 3] โครงสร้างพื้นฐานของคำสั่ง SELECT
[Normal] คำสั่ง SELECT ใช้เรียกดูข้อมูลจากฐานข้อมูล ตั้งแต่รูปแบบพื้นฐานที่เลือกทุกคอลัมน์ ไปจนถึงรูปแบบที่มีเงื่อนไขซับซ้อน คำสั่ง SELECT DISTINCT ใช้ตัดข้อมูลที่ซ้ำกันให้แสดงเพียงค่าเดียว การตั้งชื่อชั่วคราว (Alias) ช่วยให้ชื่อคอลัมน์หรือชื่อตารางอ่านง่ายขึ้น และยังสามารถนำคอลัมน์มาคำนวณในคำสั่งได้โดยตรง 
[Normal] SELECT * FROM topics;
[Normal] SELECT DISTINCT chapter_id FROM topics;
[Normal] SELECT section_no AS section, title AS topic_title
[Normal] FROM topics;
[Heading 3] การกำหนดเงื่อนไขและการเรียงลำดับข้อมูล
[Normal] การเลือกข้อมูลแบบมีเงื่อนไขทำได้โดยเพิ่มส่วน WHERE ต่อท้ายคำสั่ง ร่วมกับตัวดำเนินการเปรียบเทียบ ตัวดำเนินการ IN / NOT IN สำหรับเงื่อนไขหลายค่า และตัวดำเนินการ AND, OR, NOT สำหรับหลายเงื่อนไข (ฐาปนี, 2562, หน้า 236-237, 245-254) การค้นหาข้อความที่คล้ายกันใช้ตัวดำเนินการ LIKE ร่วมกับสัญลักษณ์ไวด์การ์ด (Wildcard) เช่น เครื่องหมาย % แทนอักขระกี่ตัวก็ได้ และการเรียงลำดับข้อมูลใช้ ORDER BY ตามด้วยชื่อคอลัมน์ ซึ่งเทียบได้กับหลักการที่แชทบอทค้นหาหัวข้อในตำราที่ตรงกับคำถามของผู้ใช้
[Normal] SELECT section_no, title
[Normal] FROM topics
[Normal] WHERE chapter_id IN (4, 5, 7)
[Normal] ORDER BY section_no;
[Normal] SELECT section_no, title FROM topics
[Normal] WHERE title LIKE '%คีย์%';
[Heading 3] ฟังก์ชันสรุปข้อมูลและการจัดกลุ่มข้อมูล
[Normal] ฟังก์ชันสรุปข้อมูล (Aggregate Functions) ประกอบด้วย MAX() หาค่ามากที่สุด MIN() หาค่าน้อยที่สุด COUNT() นับจำนวน SUM() หาผลรวม และ AVG() หาค่าเฉลี่ย เมื่อใช้ร่วมกับ GROUP BY จะสรุปข้อมูลแยกเป็นกลุ่มได้ (เช่น นับจำนวนหัวข้อในแต่ละบทของตำรา หรือนับจำนวนข้อความที่ถูกตอบด้วยแต่ละหัวข้อ เพื่อดูว่าหัวข้อใดถูกสอบถามมากที่สุด
[Normal] SELECT chapter_id, COUNT(*) AS total_topics
[Normal] FROM topics
[Normal] GROUP BY chapter_id;
[Normal] SELECT topic_id, COUNT(*) AS total
[Normal] FROM messages
[Normal] WHERE topic_id IS NOT NULL
[Normal] GROUP BY topic_id
[Normal] ORDER BY total DESC;
[Heading 2] ภาษา SQL: การเลือกข้อมูลจากหลายตารางด้วย JOIN
[Heading 3] แนวคิดการเชื่อมตาราง
[Normal] ในฐานข้อมูลเชิงสัมพันธ์ ข้อมูลที่เกี่ยวข้องกันถูกแยกเก็บในหลายตาราง การเรียกดูข้อมูลร่วมกันจึงต้องเชื่อมตารางผ่านคีย์นอกและคีย์หลักที่ตรงกัน หากไม่ระบุเงื่อนไขการเชื่อมจะเกิดการจับคู่ทุกแถวของตารางหนึ่งกับทุกแถวของอีกตารางหนึ่ง เรียกว่าคาร์ทีเซียนจอยน์ (Cartesian Join) ซึ่งทำให้ได้ผลลัพธ์จำนวนมากที่ไม่ถูกต้อง 
[Heading 3] รูปแบบของการ JOIN
[Normal] รูปแบบการเชื่อมตารางที่ตำรากล่าวถึง ได้แก่ EQUI JOIN, INNER JOIN, LEFT JOIN, RIGHT JOIN และ FULL OUTER JOIN ดังตารางที่ 2-8 และภาพที่ 2-7
[Heading 9] รูปแบบการเชื่อมตาราง (JOIN) และความหมาย
[Heading 8] ผลลัพธ์ของการเชื่อมตารางแบบต่าง ๆ (A = ตารางซ้าย, B = ตารางขวา) 
[Heading 3] ตัวอย่างการเชื่อมตารางของฐานข้อมูลแชทบอท
[Normal] ตัวอย่างต่อไปนี้ใช้ INNER JOIN แสดงข้อความพร้อมชื่อหัวข้อที่ใช้ตอบ และใช้ LEFT JOIN ร่วมกับเงื่อนไข IS NULL เพื่อค้นหาหัวข้อที่ยังไม่เคยถูกใช้ตอบคำถามของผู้ใช้ ซึ่งช่วยให้ผู้พัฒนาทราบว่าหัวข้อใดในตำรายังไม่ถูกสอบถาม (หมายเหตุ ระบบ MySQL ไม่มีคำสั่ง FULL OUTER JOIN โดยตรง จึงใช้ LEFT JOIN รวมกับ RIGHT JOIN ด้วย UNION แทน)
[Normal] SELECT m.message_text, t.title
[Normal] FROM messages AS m
[Normal] INNER JOIN topics AS t ON m.topic_id = t.topic_id;
[Normal] SELECT t.section_no, t.title
[Normal] FROM topics AS t
[Normal] LEFT JOIN messages AS m ON t.topic_id = m.topic_id
[Normal] WHERE m.msg_id IS NULL;
[Heading 2] แนวโน้มเทคโนโลยีที่เกี่ยวข้องกับฐานข้อมูล (Big Data, Machine Learning, AI และ IoT)
[Heading 4] ข้อมูลขนาดใหญ่ (Big Data)
[Normal] ข้อมูลขนาดใหญ่ (Big Data) คือชุดข้อมูลที่มีขนาดใหญ่มากจนวิธีการประมวลผลแบบเดิมไม่สามารถคำนวณ จัดเก็บ ประมวลผล และวิเคราะห์ได้ มีลักษณะสำคัญ 3 ประการ คือ ปริมาณ (Volume) ความเร็ว (Velocity) และความหลากหลาย (Variety) (รุ่งรัศมี, 2559 อ้างถึงใน ฐาปนี, 2562, หน้า 297-301)
[Heading 3] การวิเคราะห์ข้อมูล วิทยาศาสตร์ข้อมูล และเหมืองข้อมูล
[Normal] การวิเคราะห์ข้อมูล (Data Analytics) คือการนำข้อมูลขนาดใหญ่มาวิเคราะห์เพื่อสนับสนุนงานตามวัตถุประสงค์ทางธุรกิจ วิทยาศาสตร์ข้อมูล (Data Science) ใช้กระบวนการทางคณิตศาสตร์และอัลกอริทึมเพื่อหาความรู้จากข้อมูล ส่วนเหมืองข้อมูล (Data Mining) เป็นการค้นหารูปแบบที่มีคุณค่าจากข้อมูลที่จัดเก็บไว้
[Heading 3] การเรียนรู้ของเครื่อง ปัญญาประดิษฐ์ และการประมวลผลภาษาธรรมชาติ
[Normal] การเรียนรู้ของเครื่อง (Machine Learning) คือระบบที่เรียนรู้จากตัวอย่างหรือจากข้อมูลด้วยตนเองโดยไม่ต้องให้โปรแกรมเมอร์กำหนดคำสั่งทั้งหมด แบ่งเป็น 4 ประเภท เช่น การเรียนรู้แบบมีผู้สอน (Supervised Learning) ที่นำข้อมูลพร้อมผลลัพธ์ไปให้คอมพิวเตอร์เรียนรู้เพื่อสร้างโมเดลจำแนกประเภท  ปัญญาประดิษฐ์ (Artificial Intelligence: AI) คือระบบคอมพิวเตอร์หรือเครื่องจักรที่มีความสามารถในการรับรู้ เรียนรู้ ให้เหตุผล และแก้ปัญหา คล้ายการทำงานของสมองมนุษย์ และการประมวลผลภาษาธรรมชาติ (Natural Language Processing: NLP) คือการพัฒนาให้ปัญญาประดิษฐ์เข้าใจภาษาและลักษณะของมนุษย์ได้มากขึ้น ซึ่งเป็นเทคโนโลยีที่แชทบอทจำนวนมากใช้เพื่อเข้าใจข้อความของผู้ใช้ แม้ Ch-Bot จะเลือกใช้วิธีจับคู่หัวข้อแทน (ดูหัวข้อ 2.13)
[Heading 3] อินเทอร์เน็ตเพื่อสรรพสิ่ง (Internet of Things: IoT)
[Normal] สหภาพโทรคมนาคมระหว่างประเทศ (ITU) นิยาม IoT ว่าเป็นโครงข่ายสื่อสารที่เชื่อมต่ออุปกรณ์สื่อสาร เครื่องใช้ไฟฟ้า ยานพาหนะ อาคาร หรือวัตถุต่าง ๆ เข้าด้วยกัน  อุปกรณ์เหล่านี้สร้างข้อมูลจำนวนมากอย่างต่อเนื่อง ทำให้ฐานข้อมูลมีบทบาทสำคัญในการรองรับและจัดการข้อมูล
[Heading 3] ความเชื่อมโยงกับแชทบอท
[Normal] แชทบอททั่วไปนำเทคโนโลยีเหล่านี้มาใช้ร่วมกัน โดยใช้ NLP วิเคราะห์ข้อความ ใช้ฐานข้อมูลเก็บความรู้และประวัติการสนทนา และนำข้อมูลที่สะสมไปวิเคราะห์เพื่อปรับปรุงเนื้อหา ซึ่งงานวิจัยด้านแชทบอทระบุว่าการบันทึกเจตนาและพฤติกรรมของผู้ใช้ช่วยให้ผู้ดูแลปรับเนื้อหาและวัดผลการใช้งานได้ (ชาญชัย และฟ้าพราว, 2568) สำหรับ Ch-Bot เลือกใช้วิธีค้นหาหัวข้อที่ตรงกับคำถามจากตำราโดยไม่ใช้ AI แต่งคำตอบ เพื่อให้คำตอบตรงกับเนื้อหาในตำราเท่านั้น ส่วนการเรียนรู้ของเครื่องและการวิเคราะห์ข้อมูลเป็นแนวทางที่นำมาต่อยอดได้ในอนาคต
[Heading 2] ความปลอดภัยของฐานข้อมูล (Database Security)
[Heading 4] จริยธรรม ความเป็นส่วนตัว และกฎหมายที่เกี่ยวข้อง
[Normal] จริยธรรมคือหลักในการตัดสินความถูกต้องและความผิดที่บุคคลใช้เป็นแนวทางปฏิบัติ ประเด็นจริยธรรมด้านเทคโนโลยีสารสนเทศเกี่ยวข้องกับข้อมูลหลายด้าน ตำราอ้างถึงกฎหมายที่เกี่ยวข้อง ได้แก่ พระราชบัญญัติลิขสิทธิ์ พ.ศ. 2537 พระราชบัญญัติความลับทางการค้า พ.ศ. 2545 พระราชบัญญัติการรักษาความมั่นคงปลอดภัยไซเบอร์ พ.ศ. 2562 และพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 ข้อมูลที่แชทบอทจัดเก็บ เช่น ประวัติข้อความสนทนา และรหัสผู้ใช้ของแพลตฟอร์มที่เชื่อมต่อ อาจเป็นข้อมูลส่วนบุคคล จึงควรกำหนดวัตถุประสงค์ ขอบเขต และระยะเวลาในการจัดเก็บให้ชัดเจนตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 นอกจากนี้ Ch-Bot ใช้เนื้อหาจากตำราของ เป็นฐานความรู้ จึงควรแสดงแหล่งที่มาของคำตอบและตรวจสอบสิทธิ์การใช้เนื้อหาตามพระราชบัญญัติลิขสิทธิ์ พ.ศ. 2537
[Heading 3] วัตถุประสงค์ของการรักษาความปลอดภัย
[Normal] ความปลอดภัยของฐานข้อมูล (Database Security) คือการควบคุมและรักษามาตรการต่าง ๆ เพื่อรักษาความลับ ความสมบูรณ์ และความพร้อมใช้งานของฐานข้อมูล วัตถุประสงค์ของการรักษาความปลอดภัยมี 
[Normal] 4 ประการ คือ 
[Normal] 1) การรักษาความลับ (Confidentiality) ปกป้องข้อมูลจากผู้ที่ไม่ได้รับอนุญาต 
[Normal] 2) การปฏิบัติตามข้อกำหนด (Compliance) ปฏิบัติตามกฎหมายและข้อกำหนดของหน่วยงานกำกับดูแล 
[Normal] 3) ความสมบูรณ์ (Integrity) รักษาความถูกต้องและสมบูรณ์ของข้อมูล และ 
[Normal] 4) ความพร้อมใช้งาน (Availability) ให้ข้อมูลพร้อมใช้งานเสมอตามสิทธิ์ที่ได้รับ โดยหลักการทางเทคนิค 3 ข้อแรกแสดงดังภาพที่ 2-8
[Heading 8] หลักการรักษาความปลอดภัยของข้อมูล 3 ประการ 
[Heading 3] การควบคุมสิทธิ์ผู้ใช้และแนวทางรักษาความปลอดภัย
[Normal] ตำราเสนอแนวทางรักษาความปลอดภัยของฐานข้อมูล เช่น การกำหนดสิทธิ์การเข้าถึงของผู้ใช้ด้วยคำสั่ง GRANT และ REVOKE การสำรองข้อมูลเป็นระยะ การลงทุนกับซอฟต์แวร์รักษาความปลอดภัยฐานข้อมูล การแยกระดับความสำคัญของข้อมูล และการมีมาตรการป้องกันทั้งบุคคลภายนอกและบุคคลภายในองค์กร หากแชทบอทจัดเก็บข้อมูลด้วย DBMS ควรให้โปรแกรมของแชทบอทมีสิทธิ์เท่าที่จำเป็น เช่น อ่านตารางบทและหัวข้อ และเพิ่มข้อความแชต แต่ไม่ให้ลบตารางหรือแก้ไขโครงสร้างฐานข้อมูล ดังตัวอย่าง
[Normal] GRANT SELECT ON ch_bot_db.chapters TO 'bot_app'@'localhost';
[Normal] GRANT SELECT ON ch_bot_db.topics   TO 'bot_app'@'localhost';
[Normal] GRANT INSERT ON ch_bot_db.messages TO 'bot_app'@'localhost';
[Normal] REVOKE INSERT ON ch_bot_db.messages FROM 'bot_app'@'localhost';
[Heading 3] ความปลอดภัยในบริบทของแชทบอท
[Normal] ในแชทบอทที่พัฒนา ความสมบูรณ์ (Integrity) ของฐานความรู้ถูกควบคุมด้วยการตรวจสอบค่า SHA-256 ของไฟล์ความรู้ในรูปแบบ Markdown และไฟล์ตำรา PDF ต้นฉบับเทียบกับค่าที่บันทึกไว้ในไฟล์ manifest ก่อนตอบทุกครั้ง หากไฟล์หายหรือค่าไม่ตรงกันระบบจะหยุดตอบ จึงป้องกันไม่ให้แชทบอทตอบจากเนื้อหาที่ถูกแก้ไขโดยไม่ตั้งใจ ส่วนค่าลับสำหรับช่องทางเสริม เช่น token ของ LINE และ Telegram กำหนดผ่านตัวแปรสภาพแวดล้อม (Environment Variables) ของบริการที่ใช้โฮสต์ ไม่เขียนไว้ในโค้ด และเส้นทางรับข้อมูลของ Telegram จะปิดตัวเองหากไม่ได้ตั้งค่า token และ secret
[Normal] สำหรับช่องทาง LINE ซึ่งเป็นช่องทางเสริมที่รองรับในโปรแกรมแต่ยังไม่ได้เชื่อมต่อใช้งาน เอกสารของ LINE ระบุว่าเซิร์ฟเวอร์บอตอาจได้รับคำขอที่ไม่ได้มาจาก LINE Platform และอาจเป็นอันตราย จึงต้องตรวจสอบลายเซ็นในส่วนหัวของคำขอก่อนประมวลผลเหตุการณ์ทุกครั้ง (LINE Developers, n.d.-b) และที่อยู่ Webhook ต้องเป็น HTTPS ที่ใช้ใบรับรองจากหน่วยงานที่เชื่อถือได้ (LINE Developers, n.d.-c) หากในอนาคตจัดเก็บข้อมูลด้วย DBMS ควรตรวจสอบและกรองข้อความที่ผู้ใช้พิมพ์เข้ามาก่อนนำไปประกอบคำสั่ง SQL เพื่อป้องกันการโจมตีแบบ SQL Injection และควรสำรองข้อมูลเป็นระยะเพื่อให้กู้คืนระบบได้เมื่อเกิดความเสียหาย
[Heading 2] หลักการพัฒนาแชทบอท (Chatbot Development Principles)
[Heading 3] ความหมายและพัฒนาการของแชทบอท
[Normal] แชทบอท (Chatbot) คือซอฟต์แวร์ที่สนทนาโต้ตอบกับผู้ใช้โดยอัตโนมัติด้วยภาษาธรรมชาติ ทั้งในรูปแบบข้อความหรือเสียงพูด และสามารถตอบคำถามได้ตลอด 24 ชั่วโมง (เจษฎา และคณะ, 2567) แชทบอทในยุคแรกคือโปรแกรม ELIZA ที่ Weizenbaum (1966) พัฒนาขึ้นเพื่อศึกษาการสื่อสารด้วยภาษาธรรมชาติระหว่างมนุษย์กับเครื่อง ต่อมาแชทบอทถูกนำไปใช้อย่างแพร่หลายในหลายสาขา เช่น การตลาด ระบบสนับสนุนลูกค้า การศึกษา การดูแลสุขภาพ มรดกทางวัฒนธรรม และความบันเทิง (Adamopoulou & Moussiades, 2020)
[Heading 3] ประเภทของแชทบอทตามวิธีสร้างคำตอบ
[Normal] Adamopoulou และ Moussiades (2020) จำแนกแชทบอทตามวิธีประมวลผลข้อความและสร้างคำตอบเป็น 3 แบบ ดังตารางที่ 2-9
[Heading 9] การเปรียบเทียบแชทบอท 3 แบบตามวิธีสร้างคำตอบ
[Normal] Ch-Bot จัดอยู่ในกลุ่มแบบค้นคืนอย่างเรียบง่าย คือเลือกหัวข้อในตำราที่ตรงกับคำถามด้วยการเทียบคำกับชื่อหัวข้อและตารางคำพ้อง (Lexical Retrieval) แล้วแสดงเนื้อหาหัวข้อนั้นโดยตรง ไม่สร้างข้อความตอบใหม่ จึงไม่ใช่แบบสร้างคำตอบ และหากไม่มีหัวข้อที่ตรงกับคำถามจะตอบว่าไม่มีข้อมูลเรื่องนี้ในตำรา ซึ่งช่วยควบคุมไม่ให้คำตอบเบี่ยงเบนไปจากแหล่งความรู้ แต่ก็หมายความว่าบอทไม่สามารถเขียนคำสั่ง SQL ใหม่ตามโจทย์ของผู้ใช้ได้
[Heading 3] สถาปัตยกรรมและองค์ประกอบของแชทบอท
[Normal] แชทบอทสมัยใหม่ประกอบด้วยองค์ประกอบหลัก (Adamopoulou & Moussiades, 2020) ได้แก่
[Heading 4] ส่วนวิเคราะห์ข้อความของผู้ใช้ (User Message Analysis) ทำหน้าที่ระบุเจตนา (Intent) และเอนทิตี (Entity) จากข้อความ
[Heading 4] ส่วนจัดการบทสนทนา (Dialogue Management) เก็บและปรับปรุงบริบทของบทสนทนา เช่น เจตนาปัจจุบัน ข้อมูลที่ระบุได้แล้ว และข้อมูลที่ยังขาด รวมถึงถามติดตามเมื่อข้อมูลไม่ครบ
[Heading 4] ส่วนสร้างคำตอบ (Response Generation) เตรียมคำตอบเป็นภาษาธรรมชาติตามเจตนาและบริบทที่ได้
[Normal] Ch-Bot ที่พัฒนาขึ้นมีลำดับการทำงานดังภาพที่ 2-9 คือ ผู้เรียนพิมพ์คำถามผ่านหน้าเว็บแชต เซิร์ฟเวอร์ Flask ส่งคำถามให้โมดูล knowledge_base.py ซึ่งตรวจสอบไฟล์ความรู้กับ manifest แล้วค้นหัวข้อในตำราที่ตรงกับคำถามโดยเทียบกับชื่อหัวข้อและตารางคำพ้อง จากนั้นแสดงเนื้อหาหัวข้อนั้นพร้อมบรรทัดแหล่งที่มาให้ผู้เรียน โดยหน้าเว็บเก็บประวัติแชตไว้ใน localStorage ของเบราว์เซอร์ ส่วนช่องทาง LINE และ Telegram เป็นช่องทางเสริมที่โปรแกรมรองรับผ่าน Webhook แต่ยังไม่ได้เชื่อมต่อใช้งาน
[Heading 8] สถาปัตยกรรมของแชทบอท Ch-Bot 
[Normal] สำหรับแชทบอทที่ให้บริการผ่านแอปพลิเคชัน LINE ลำดับการทำงานคือ ผู้ใช้ส่งข้อความไปยัง LINE Official Account จากนั้น LINE Platform ส่ง Webhook Event ไปยัง URL ของเซิร์ฟเวอร์บอต และเซิร์ฟเวอร์บอตตรวจสอบเหตุการณ์แล้วตอบกลับผู้ใช้ผ่าน LINE Platform (LINE Developers, n.d.-a) ซึ่งเป็นรูปแบบเดียวกับที่ใช้ในงานวิจัยของ เจษฎา และคณะ (2567) และ ชาญชัย และฟ้าพราว (2568)
[Heading 3] เทคโนโลยีและแพลตฟอร์มที่เกี่ยวข้อง
[Normal] Python และ Flask Ch-Bot พัฒนาด้วยภาษา Python และเฟรมเวิร์ก Flask โดยไฟล์ app.py ทำหน้าที่เซิร์ฟเวอร์เว็บและรับ Webhook ส่วน knowledge_base.py โหลดตำรา ตรวจ checksum และค้นหาหัวข้อที่ตรงกับคำถาม ระบบให้บริการผ่านหน้าเว็บแชตที่ติดตั้งบน Vercel
[Normal] ฐานความรู้ ตำรา ฐาปนี (2562) จำนวน 426 หน้า (12 บท และภาคผนวก ก ข) ถูกดึงข้อความด้วย PyMuPDF แล้วแบ่งตามสารบัญ 134 รายการ ได้เป็น 172 หัวข้อ ประกอบด้วยหัวข้อย่อย บทนำ บทสรุป และแบบฝึกหัดของแต่ละบท หัวข้อที่ยาวเกินประมาณ 3,500 ตัวอักษรถูกแบ่งตามหัวข้อย่อยในเล่ม และครอบคำสั่ง SQL ด้วยบล็อกโค้ด มีไฟล์ manifest.json เก็บชื่อไฟล์ ค่า SHA-256 และจำนวนหัวข้อ ส่วนที่ไม่ได้แปลง คือ ภาพและแผนภาพ บรรณานุกรม ดัชนี และประวัติผู้เขียน
[Normal] LINE Messaging API เป็นช่องทางที่ Ch-Bot รองรับเป็นช่องทางเสริม โดยเซิร์ฟเวอร์บอตรับและส่งข้อมูลกับ LINE Platform ผ่าน HTTPS ในรูปแบบ JSON สามารถส่งข้อความตอบกลับผู้ใช้ที่เพิ่ม LINE Official Account เป็นเพื่อน และส่งข้อความหาผู้ใช้ได้ทุกเวลา (LINE Developers, n.d.-a) ทุกครั้งที่ผู้ใช้เพิ่มบัญชีเป็นเพื่อนหรือส่งข้อความ LINE Platform จะส่งคำขอ HTTP POST ที่มี Webhook Event ไปยัง URL ที่ลงทะเบียนไว้ (LINE Developers, n.d.-b)
[Normal] Dialogflow เป็นแพลตฟอร์มของ Google ที่ใช้ในงานวิจัยที่ศึกษา สำหรับสร้างบอทสนทนาโดยใช้การเรียนรู้ของเครื่องและการประมวลผลภาษาธรรมชาติช่วยทำความเข้าใจความต้องการของผู้ใช้ ทำให้ไม่จำเป็นต้องพิมพ์ข้อความตรงกับเงื่อนไขแบบ Rule-based ทุกประการ องค์ประกอบพื้นฐานของบทสนทนา ได้แก่ Intent คือประโยคที่คาดว่าผู้ใช้จะส่งเข้ามา Response คือข้อความตอบกลับของ Intent และ Integration คือการเชื่อมต่อกับช่องทางอื่น เช่น LINE (ชาญชัย และฟ้าพราว, 2568) เอกสารของ Google Cloud (n.d.) ระบุว่า Dialogflow ES มีแนวคิดหลักด้าน Agent, Intent, Training Phrases, Entities, Contexts และ Fulfillment ผ่าน Webhook ซึ่ง Ch-Bot ไม่ได้ใช้แพลตฟอร์มนี้
[Normal] ฐานข้อมูลและเครื่องมือจัดการข้อมูลในงานวิจัยที่ศึกษา งานวิจัยที่ศึกษาใช้ทั้งฐานข้อมูลเชิงสัมพันธ์ MySQL ร่วมกับ PHP และ Laravel Framework (เจษฎา และคณะ, 2567) และใช้ Google Sheets เป็นที่เก็บข้อมูลร่วมกับ Google Apps Script ซึ่งเป็นเครื่องมือบนคลาวด์ที่เขียนด้วย JavaScript เพื่อเพิ่ม ลบ แก้ไข และดึงข้อมูล (ชาญชัย และฟ้าพราว, 2568)
[Heading 3] หลักการออกแบบบทสนทนาและการจัดการข้อมูลของแชทบอท
[Normal] จากงานวิจัยที่ศึกษา สรุปหลักการพัฒนาแชทบอทที่เกี่ยวข้องกับการจัดการข้อมูลได้ดังนี้
[Normal] 1) กำหนดขอบเขตจากความต้องการจริงของผู้ใช้ เช่น เจษฎา และคณะ (2567) สำรวจคำถามจากนักศึกษา 200 คน แล้วคัดเลือกประเภทคำถามที่มีผู้ตอบมากกว่าร้อยละ 75 ได้ 8 ประเภท
[Normal] 2) ออกแบบโครงสร้างบทสนทนา (Conversational Flow) ให้มี Intent ต้อนรับ Intent คำถามหลัก Intent สำรองเมื่อไม่เข้าใจ (Fallback) และ Intent จบการสนทนา (เจษฎา และคณะ, 2567; ชาญชัย และฟ้าพราว, 2568)
[Normal] 3) แยกคำตอบที่คงที่ออกจากคำตอบที่เปลี่ยนแปลงบ่อย โดยเก็บคำตอบคงที่ไว้ในแพลตฟอร์มประมวลผลภาษา และเก็บคำตอบที่เปลี่ยนแปลง เช่น ปฏิทินและที่ตั้งอาคาร ไว้ในฐานข้อมูล (เจษฎา และคณะ, 2567)
[Normal] 4) จัดทำหน้าเว็บสำหรับผู้ดูแลระบบเพื่อเพิ่ม ลบ แก้ไข และค้นหาข้อมูลคำตอบ เพื่อให้ข้อมูลเป็นปัจจุบันโดยไม่ต้องแก้ไขโปรแกรม (เจษฎา และคณะ, 2567; ชาญชัย และฟ้าพราว, 2568)
[Normal] 5) บันทึกเจตนาและพฤติกรรมของผู้ใช้เพื่อนำไปวิเคราะห์และปรับปรุงเนื้อหา (ชาญชัย และฟ้าพราว, 2568)
[Normal] 6) ทดสอบระบบด้วยชุดคำถามทดสอบก่อนใช้งานจริง เช่น เจษฎา และคณะ (2567) ทดสอบ 14 ข้อ ได้ผลตรงตามที่กำหนด 12 ข้อ และพบว่าข้อผิดพลาดเกิดจากการดึงข้อมูลจากฐานข้อมูลผิดและการหมดเวลาในการเชื่อมต่อ Webhook กับ Dialogflow
[Normal] 7) คำนึงถึงความปลอดภัยและข้อมูลส่วนบุคคลของผู้ใช้ตามหัวข้อ 2.12
[Normal] สำหรับ Ch-Bot ผู้จัดทำนำหลักการเหล่านี้มาปรับใช้ โดยกำหนดให้ตำราเป็นแหล่งความรู้เพียงแหล่งเดียว ตอบด้วยเนื้อหาหัวข้อที่ตรงกับคำถามพร้อมแสดงแหล่งที่มา และหากไม่มีหัวข้อที่ตรงกันจะตอบว่าไม่มีข้อมูลเรื่องนี้ในตำรา โดยค้นจากชื่อหัวข้อเท่านั้น ไม่ค้นในเนื้อหา เพราะคำที่ปรากฏในเนื้อหาเพียงผ่าน ๆ ไม่ได้แปลว่าตำราอธิบายเรื่องนั้น (เช่น คำว่า Transaction ที่อยู่ในตาราง) และลดคะแนนหัวข้อบทนำ บทสรุป และแบบฝึกหัด เว้นแต่ผู้ใช้ถามถึงเอง นอกจากนี้ระบบรองรับการถามด้วยเลขหัวข้อหรือบทของแบบฝึกหัด จำกัดความยาวคำตอบบน LINE และ Telegram ให้ไม่เกินหนึ่งข้อความโดยยังคงบรรทัดแหล่งที่มา ตรวจความสมบูรณ์ของไฟล์ความรู้ก่อนตอบ และมีชุดทดสอบอัตโนมัติด้วย unittest จำนวน 17 รายการ ครอบคลุมการตรวจว่าคำตอบมีเฉพาะเนื้อหาที่จัดเก็บไว้ การหยุดตอบเมื่อไฟล์หายหรือ checksum ไม่ตรง และการตอบว่าไม่มีข้อมูลสำหรับคำถามนอกตำรา ทั้งนี้การค้นหาแบบเทียบชื่อหัวข้อไม่รับประกันว่าจะตรงกับทุกคำถาม เช่น คำถามเรื่องการตั้งรหัสผ่านใน Access อาจได้หัวข้อในภาคผนวก ข แทนหัวข้อ 12.5 และเนื่องจากตำราใช้ Microsoft Access เป็นหลัก ตัวอย่างคำสั่ง SQL บางส่วนที่บอทแสดงจึงเป็นรูปแบบเฉพาะของ Access

[Normal] เจษฎา และคณะ (2567) พัฒนาแอปพลิเคชันแชตบอตสำหรับงานบริการนักศึกษา มหาวิทยาลัยราชภัฏบุรีรัมย์ ตามวงจรการพัฒนาระบบ (SDLC) โดยใช้ PHP, Laravel Framework, ฐานข้อมูล MySQL, LINE Bot Designer และ Dialogflow แชทบอทตอบคำถามได้ 8 ด้าน เช่น การลงทะเบียนเรียน ปฏิทินการศึกษา และที่ตั้งอาคาร โดยเก็บคำตอบคงที่ไว้ใน Dialogflow และเก็บคำตอบที่เปลี่ยนแปลงไว้ในฐานข้อมูล MySQL พร้อมเว็บแอปพลิเคชันให้เจ้าหน้าที่จัดการคำตอบ การออกแบบเชิงวัตถุประกอบด้วย 7 คลาส คือ User, Chatbot, academics, activities, maps, location และ Admin ผลการประเมินโดยนักศึกษา 100 คน พบว่ามีความพึงพอใจอยู่ในระดับมาก (ค่าเฉลี่ย 4.42, S.D. = 0.65)

[Heading 2] บทสรุป
[Normal] จากการศึกษาทฤษฎีและเอกสารที่เกี่ยวข้องกับการพัฒนาแชทบอทตอบคำถามเรื่องฐานข้อมูลและ SQL (Ch-Bot ครูเอสคิว) ประกอบด้วยความรู้พื้นฐานเกี่ยวกับข้อมูล สารสนเทศ และระบบแฟ้มข้อมูล ซึ่งมีข้อจำกัดด้านความซ้ำซ้อนและการขึ้นต่อโปรแกรม จึงนำไปสู่ระบบฐานข้อมูลที่มีระบบจัดการฐานข้อมูลเป็นตัวกลางและมีสถาปัตยกรรม 3 ระดับที่ทำให้ข้อมูลเป็นอิสระจากโปรแกรม การออกแบบฐานข้อมูลเริ่มจากแบบจำลองเชิงสัมพันธ์และชนิดของคีย์ นำมาสร้างแผนภาพอีอาร์ แปลงเป็นรีเลชันพร้อมพจนานุกรมข้อมูล และปรับให้อยู่ในนอร์มัลฟอร์มระดับที่ 3 เพื่อลดความซ้ำซ้อน จากนั้นใช้ภาษา SQL สร้างตารางและจัดการข้อมูลด้วยคำสั่ง CREATE, INSERT, UPDATE, DELETE เรียกดูข้อมูลด้วย SELECT และเชื่อมข้อมูลหลายตารางด้วย JOIN ซึ่งเป็นเนื้อหาที่แชทบอทใช้ตอบคำถามผู้เรียน
[Normal] นอกจากนี้ยังศึกษาแนวโน้มเทคโนโลยีด้านข้อมูลขนาดใหญ่ การเรียนรู้ของเครื่อง ปัญญาประดิษฐ์ และ IoT ศึกษาความปลอดภัยของฐานข้อมูลตามหลักการรักษาความลับ ความสมบูรณ์ และความพร้อมใช้งาน รวมถึงการปฏิบัติตามกฎหมายคุ้มครองข้อมูลส่วนบุคคลและลิขสิทธิ์ ส่วนหลักการพัฒนาแชทบอทประกอบด้วยประเภทของแชทบอท องค์ประกอบด้านการวิเคราะห์ข้อความและการสร้างคำตอบ การเชื่อมต่อกับช่องทางต่าง ๆ เช่น LINE Messaging API และแพลตฟอร์มประมวลผลภาษา เช่น Dialogflow งานวิจัยที่เกี่ยวข้องแสดงให้เห็นว่าการแยกคำตอบคงที่ออกจากคำตอบที่เปลี่ยนแปลงในที่เก็บข้อมูล และการมีส่วนจัดการข้อมูลสำหรับผู้ดูแลระบบ เป็นแนวทางที่ใช้ได้จริงและได้รับความพึงพอใจจากผู้ใช้ในระดับมากถึงมากที่สุด ขณะที่ Ch-Bot เลือกใช้วิธีจับคู่คำถามกับหัวข้อในตำราและตอบด้วยเนื้อหาจากตำราโดยตรง เพื่อให้คำตอบตรวจสอบย้อนกลับได้

[Heading 2] แบบแผนการวิจัย
[Normal] การวิจัยเรื่อง "การพัฒนา Chatbot เพื่อการเรียนรู้เรื่องระบบฐานข้อมูลและภาษา SQL" ผู้วิจัยได้กำหนดรูปแบบการวิจัยเป็นการวิจัยและพัฒนา (Research and Development: R&D) โดยมีวัตถุประสงค์เพื่อ 1) พัฒนา Chatbot AI สำหรับตอบคำถามและสนับสนุนการเรียนรู้เกี่ยวกับการจัดการฐานข้อมูลและภาษา SQL และ 2) ประเมินประสิทธิภาพและความแม่นยำของ Chatbot AI สำหรับตอบคำถามเกี่ยวกับการจัดการฐานข้อมูลและภาษา SQL ที่พัฒนาขึ้น โดยแบ่งขั้นตอนการดำเนินการวิจัยออกเป็น 3 ระยะหลัก ได้แก่
[Normal] ระยะที่ 1 การศึกษาและวิเคราะห์ความต้องการ (Analysis & Design): ศึกษาขอบเขตเนื้อหาด้านการจัดการฐานข้อมูลและไวยากรณ์คำสั่งภาษา SQL พื้นฐาน วิเคราะห์สถาปัตยกรรมระบบปัญญาประดิษฐ์และการประมวลผลภาษาธรรมชาติ (NLP) เพื่อนำมากำหนดกรอบการพัฒนา
[Normal] ระยะที่ 2 การพัฒนาและทดสอบระบบจำลอง (Development & Pilot Test): ดำเนินการสร้างระบบ Chatbot เชื่อมต่อกับระบบฐานข้อมูลจำลอง (Database Sandbox Engine) จัดทำคลังความรู้ (Knowledge Base) และนำระบบไปทดสอบเบื้องต้นเพื่อปรับปรุงข้อบกพร่อง
[Normal] ระยะที่ 3 การประเมินประสิทธิภาพและความแม่นยำ (Evaluation & Accuracy Assessment): ทำการทดสอบประสิทธิภาพความถูกต้องแม่นยำของ Chatbot ด้วยชุดคำถามทดสอบมาตรฐาน (Evaluation Dataset) และวิเคราะห์ผลเพื่อนำเสนอในบทที่ 4
[Heading 8] กรอบแนวทางการวิจัยและพัฒนา Chatbot เพื่อการเรียนรู้เรื่องระบบฐานข้อมูลและภาษา SQL
[Heading 2] ประชากรและกลุ่มตัวอย่าง
[Heading 3] ประชากร : นักศึกษาระดับปริญญาตรี สาขาวิทยาการคอมพิวเตอร์ หรือเทคโนโลยีสารสนเทศ (หรือสาขาที่เกี่ยวข้อง) ที่ลงทะเบียนเรียนวิชาระดับเบื้องต้นเกี่ยวกับระบบฐานข้อมูล จำนวน 30 คน
[Heading 3] กลุ่มตัวอย่าง : นักศึกษาที่ได้จากการสุ่มกลุ่มตัวอย่างแบบเจาะจง (Purposive Sampling) จำนวน [ระบุ เช่น 30-50] คน ที่กำลังศึกษาวิชาฐานข้อมูลในภาคนั้นๆ
[Heading 2] เครื่องมือที่ใช้ในงานวิจัย
[Normal] เครื่องมือที่ใช้ในงานวิจัยแบ่งออกเป็น 2 ประเภท ได้แก่
[Heading 3] เครื่องมือที่ใช้ในการพัฒนาระบบ (Development Tools):
[Normal] ระบบ Chatbot เพื่อการเรียนรู้เรื่องระบบฐานข้อมูลและภาษา SQL:พัฒนาขึ้นโดยใช้
[Normal] เทคโนโลยี Large Language Model (LLM API) ร่วมกับเทคนิค Prompt Engineering และ Retrieval-Augmented Generation (RAG) สำหรับสืบค้นและตอบคำถามเชิงเทคนิค
[Normal] ระบบฐานข้อมูลทดสอบ (Database Engine) PostgreSQL / MySQL / SQLite สำหรับ
[Normal] ให้ Chatbot ส่ง Query ไปประมวลผลจริง
[Normal] ส่วนติดต่อกับผู้ใช้ (User Interface) ให้บริการผ่าน Web Application เพื่อให้ผู้เรียน
[Normal] สามารถพิมพ์สนทนาและทดสอบโค้ด SQL ได้สะดวก
[Heading 3] เครื่องมือที่ใช้ในการประเมินประสิทธิภาพและความแม่นยำ (Evaluation Tools)
[Normal] แบบประเมินความถูกต้องและความแม่นยำ (Accuracy Assessment Form) ใช้สำหรับ
[Normal] บันทึกและตรวจวัดผลการประเมินการตอบสนองของระบบ
[Normal] แบบประเมินความพึงพอใจของผู้ใช้งานต่อระบบ Chatbot (ใช้มาตราส่วนประมาณค่า 5 ระดับของ Likert Scale)
[Heading 2] การสร้างและหาคุณภาพเครื่องมือที่ใช้ในงานวิจัย
[Normal] ผู้วิจัยได้ดำเนินการสร้างและพัฒนาเครื่องมือตามลำดับขั้นตอน ดังนี้
[Heading 3] การสร้างและพัฒนา Chatbot ช่วยสอนระบบฐานข้อมูลและภาษา SQL
[Normal] 1. การศึกษาและวิเคราะห์เนื้อหา (Content Analysis) ศึกษาทฤษฎีฐานข้อมูลเชิงสัมพันธ์ โครงสร้างคำสั่ง SQL และเทคนิคการประมวลผลภาษาธรรมชาติ (NLP) รวมถึงการประยุกต์ใช้โมเดลภาษาขนาดใหญ่ (LLM API)
[Normal] 2. การออกแบบสถาปัตยกรรมระบบ ผู้วิจัยได้ออกแบบโครงสร้างระบบแบ่งออกเป็น 2
[Normal] ส่วนหลัก ได้แก่ 
[Normal] ส่วนที่ 1 ส่วนของผู้ใช้ (User Interface): ผู้เรียนสามารถโต้ตอบกับ Chatbot โดยมีฟังก์ชันหลัก ได้แก่ 1) ช่องสนทนาสอบถามข้อสงสัยเกี่ยวกับไวยากรณ์ SQL และแนวคิดฐานข้อมูล 2) พื้นที่ทดสอบเขียนโค้ด (SQL Code Playground) ให้ผู้เรียนสามารถทดลองส่งคำสั่ง Query และรับผลลัพธ์ข้อมูลกลับมาได้ทันที 3) ฟังก์ชันขอรับคำใบ้ (Hint) และคำอธิบายข้อผิดพลาด (Syntax Error Explanation) 
[Normal] ส่วนที่ 2 ส่วนของ Chatbot Engine & Database Backend: ทำหน้าที่รับข้อความจากผู้ใช้ นำเข้าสู่โมเดล NLP เพื่อจำแนกเจตนา (Intent Recognition) ดึงข้อมูลความรู้จากฐานข้อมูลองค์ความรู้ (Knowledge Base) ที่จัดเตรียมไว้ และเชื่อมโยงคำสั่งไปยัง Sandbox Database เพื่อตรวจสอบความถูกต้องของไวยากรณ์และส่งคำอธิบายกลับมายังผู้เรียน 
[Normal] 3. การออกแบบ System Prompt และ Persona: กำหนดบทบาทให้ Chatbot ทำหน้าที่
[Normal] เป็น "ผู้ช่วยสอนอัจฉริยะวิชาระบบฐานข้อมูลและภาษา SQL" มีความเป็นมิตร ใช้คำอธิบายที่เข้าใจง่าย พร้อมยกตัวอย่างตารางจำลองประกอบเสมอ โดยกำหนด System Instructions ชัดเจนว่า "หากผู้เรียนถามแนวทางการเขียน Query ให้เน้นการอธิบายโครงสร้างคำสั่ง หลักการคัดกรอง และชี้แนะข้อผิดพลาด ไม่ให้พิมพ์เฉลยทั้งหมดในทันที เพื่อกระตุ้นให้ผู้เรียนได้ฝึกคิดวิเคราะห์ด้วยตนเอง"
[Normal] 4. การเตรียมคลังความรู้และการเทรนระบบ (Knowledge Base Integration): รวบรวม
[Normal] เอกสารประกอบการสอน สไลด์บรรยาย ตัวอย่างคำสั่ง SQL (SELECT, WHERE, JOIN, GROUP BY, INSERT, UPDATE, DELETE) และเอกสารนิยามโครงสร้างฐานข้อมูลเชิงสัมพันธ์ จัดทำเป็นฐานข้อมูลเวกเตอร์ (Vector Database) เพื่อให้ระบบสามารถสืบค้นเนื้อหาตอบคำถามได้อย่างแม่นยำ
[Normal] 5. การนำเสนออาจารย์ที่ปรึกษา: นำระบบที่พัฒนาขึ้นให้อาจารย์ที่ปรึกษาพิจารณาความ
[Normal] เหมาะสมของเนื้อหาและโครงสร้าง เพื่อปรับปรุงแก้ไข
[Normal] 6. การตรวจสอบคุณภาพโดยผู้เชี่ยวชาญ นำระบบให้ผู้เชี่ยวชาญด้านเทคโนโลยี
[Normal] สารสนเทศและวิทยาการคอมพิวเตอร์ จำนวน 5 ท่าน ประเมินคุณภาพระบบ
[Normal] 7. การทดลองใช้ระบบเบื้องต้น (Pilot Test) นำ Chatbot ไปทดลองใช้กับกลุ่มนักศึกษา
[Normal] ที่ไม่ใช่กลุ่มตัวอย่าง จำนวน 10 คน เพื่อทดสอบการรับส่งคำสั่ง ตรวจสอบความถูกต้องของการแปลงข้อความ (Text-to-SQL) และนำข้อบกพร่องที่พบมาปรับปรุงแก้ไขระบบให้มีความเสถียรและแม่นยำสูงสุดก่อนนำไปใช้จริง
[Heading 8] กรอบแนวทางการสร้างและพัฒนา Chatbot ช่วยสอนระบบฐานข้อมูลและภาษา SQL
[Heading 3] การสร้างชุดข้อสอบและแบบประเมินความแม่นยำของระบบ
[Normal] 1. ศึกษาเนื้อหาและมาตรฐานคำสั่ง SQL: วิเคราะห์ขอบเขตเนื้อหาตามวัตถุประสงค์
[Normal] งานวิจัยเพื่อกำหนดกรอบคำถามทดสอบความแม่นยำ
[Normal] 2. ออกแบบชุดคำถามทดสอบ (Evaluation Dataset): สร้างชุดคำถามและโจทย์ภาษา
[Normal] SQL จำนวน 100 ข้อ ครอบคลุมทั้งเชิงทฤษฎี การเขียน Query และการแก้ Syntax Error
[Normal] 3. นำเสนออาจารย์ที่ปรึกษา: ตรวจสอบความถูกต้อง ความชัดเจนของภาษา และความ
[Normal] ครอบคลุมของโจทย์ทดสอบ
[Normal] 4. ตรวจสอบความตรงเชิงเนื้อหาโดยผู้เชี่ยวชาญ (IOC): นำชุดคำถามและเกณฑ์ประเมิน
[Normal] ให้ผู้เชี่ยวชาญ 5 ท่าน พิจารณาหาค่าดัชนีความสอดคล้อง (IOC) โดยคัดเลือกเฉพาะข้อที่มีค่า IOC 
[Normal] 5. จัดทำแบบประเมินความแม่นยำฉบับสมบูรณ์: เพื่อใช้เป็นเครื่องมือมาตรฐานในการ
[Normal] ทดสอบและบันทึกผลการประเมินความถูกต้องในบทที่ 4กรอบแนวทางการสร้างชุดคำถามและแบบประเมินความแม่นยำของระบบ

[Normal] 3. อัตราความถูกต้องของคำอธิบายและแนวคิดฐานข้อมูล (Explanation Accuracy Rate) ร้อยละของคำอธิบายเชิงทฤษฎีและแนวทางการแก้ปัญหาที่ถูกต้องตามหลักวิชาการ

[Heading 2] ผลการประเมินระดับรายบุคคล
[Normal] ในการประเมินประสิทธิภาพการทำนายของแชตบอต ผู้วิจัยได้กำหนดเกณฑ์การประเมินตามโครงสร้าง Evaluation Matrix (Confusion Matrix) โดยจำแนกรูปแบบการประเมินผลออกเป็น 4 เกณฑ์ ดังนี้
[Normal] คะแนน 1 (TP - True Positive): แชตบอตทำนายว่า "ใช่" และผลจริงคือ "ใช่" หมายถึง แชตบอตสามารถตอบคำถามในขอบเขตเนื้อหาได้อย่างถูกต้อง
[Normal] คะแนน 2 (FP - False Positive): แชตบอตทำนายว่า "ใช่" แต่ผลจริงคือ "ไม่ใช่" หมายถึง แชตบอตให้คำตอบที่ไม่ตรงกับเจตนา คำตอบคลาดเคลื่อน หรือตอบผิดพลาด (False Alarm)
[Normal] คะแนน 3 (TN - True Negative): แชตบอตทำนายว่า "ไม่ใช่" และผลจริงคือ "ไม่ใช่" หมายถึง แชตบอตปฏิเสธคำถามนอกขอบเขตได้อย่างถูกต้อง
[Normal] คะแนน 4 (FN - False Negative): แชตบอตทำนายว่า "ไม่ใช่" แต่ผลจริงคือ "ใช่" หมายถึง แชตบอตไม่สามารถตอบคำถามที่อยู่ในขอบเขตเนื้อหาได้ (Missed)
[Normal] การคำนวณค่าความแม่นยำระดับรายบุคคล () คำนวณจากสูตร:
[Normal] จากการทดสอบประเมินแชตบอตกับผู้ทดสอบจำนวน 6 คน โดยผู้ทดสอบแต่ละคนทำการทดสอบถามคำถามคนละ 110 ข้อ (รวมชุดข้อมูลทดสอบทั้งสิ้น 660 ข้อ) ปรากฏผลการประเมินระดับรายบุคคลดังตารางที่ 4.1

[Heading 2] ผลการประเมินระดับกลุ่ม
[Normal] เพื่อวิเคราะห์ความแตกต่างระหว่างผู้ที่มีความคุ้นเคยกับระบบและผู้ใช้งานทั่วไป ผู้วิจัยได้แบ่งกลุ่มผู้ทดสอบออกเป็น 2 กลุ่ม ได้แก่ กลุ่มสมาชิกภายในกลุ่ม (ผู้ทดสอบคนที่ 1–3) และ กลุ่มสมาชิกภายนอกกลุ่ม (ผู้ทดสอบคนที่ 4–6) โดยคำนวณจากผลรวมจำนวนคำตอบที่ถูกต้องของทุกคนในกลุ่ม หารด้วยจำนวนคำถามทั้งหมดของกลุ่มนั้นๆ ตามสูตร:
[Normal] ผลการเปรียบเทียบประสิทธิภาพการทำนายแยกตามกลุ่มผู้ใช้งาน ปรากฏดังตารางที่ 4.2
[Heading 9] ผลการประเมินความแม่นยำการทำนายของแชตบอตแยกตามกลุ่มผู้ใช้งาน
[Normal] จากตารางที่ 4.2 พบว่า กลุ่มสมาชิกภายนอกกลุ่ม มีค่าความแม่นยำในการใช้งานแชตบอตเท่ากับร้อยละ 78.48 (ตอบถูกต้อง 259 ข้อ จาก 330 ข้อ) ซึ่งสูงกว่า กลุ่มสมาชิกภายในกลุ่ม ที่มีค่าความแม่นยำเท่ากับร้อยละ 77.88 (ตอบถูกต้อง 257 ข้อ จาก 330 ข้อ) เล็กน้อย โดยมีความแตกต่างกันเพียงร้อยละ 0.60 ชี้ให้เห็นว่าแชตบอตสามารถเข้าใจบริบทและภาษาธรรมชาติของผู้ใช้งานทั่วไปได้ดีใกล้เคียงกับผู้พัฒนาระบบ
[Heading 2] ผลการประเมินระดับภาพรวม
[Normal] การประเมินประสิทธิภาพในภาพรวมของแชตบอต คำนวณจากผลรวมของค่าประเมินจากผู้ทดสอบทั้ง 6 คน รวมชุดข้อมูลคำถามทั้งสิ้น 660 ข้อ ตามสูตร:
[Normal] ผลการประเมินประสิทธิภาพความแม่นยำในภาพรวม สรุปได้ดังตารางที่ 4.3
[Heading 9] สรุปผลการประเมินประสิทธิภาพความแม่นยำของแชตบอตในภาพรวม
[Normal] จากตารางที่ 4.3 สรุปผลการประเมินประสิทธิภาพแชตบอตในภาพรวมจากการทดสอบจำนวน 660 ข้อ พบว่า แชตบอตสามารถตอบคำถามและทำนายผลได้ถูกต้องรวมทั้งสิ้น 516 ข้อ (แบ่งเป็น True Positive 378 ข้อ และ True Negative 138 ข้อ) คิดเป็นค่าความแม่นยำในภาพรวม (Overall Accuracy) เท่ากับ ร้อยละ 78.18 ขณะที่มีข้อผิดพลาดในการทำนายรวม 144 ข้อ (False Positive ร้อยละ 11.36 และ False Negative ร้อยละ 10.45) ซึ่งสามารถนำข้อมูลข้อผิดพลาดดังกล่าวไปใช้ในการปรับปรุง คลังข้อมูล (Knowledge Base) และการจัดการเจตนาของคำถาม (Intent Recognition) ให้มีประสิทธิภาพสูงขึ้นต่อไป

[Heading 3] ผลการพัฒนา Chatbot
[Normal] การวิจัยครั้งนี้ได้พัฒนา Chatbot เพื่อการเรียนรู้เรื่องระบบฐานข้อมูลและภาษา SQL โดยมีวัตถุประสงค์เพื่อใช้เป็นเครื่องมือสนับสนุนการเรียนรู้และช่วยตอบข้อสงสัยของผู้เรียน ผู้วิจัยได้ศึกษาและรวบรวมเนื้อหาจากหนังสือ การจัดการระบบฐานข้อมูลเพื่องานธุรกิจ ของ ฐาปนี เพ็งสุข (2562) เพื่อนำมาใช้เป็นข้อมูลในการจัดทำฐานความรู้ของ Chatbot โดยเนื้อหาครอบคลุมความรู้พื้นฐานเกี่ยวกับระบบฐานข้อมูล ระบบจัดการฐานข้อมูล องค์ประกอบและโครงสร้างของฐานข้อมูล ตารางและความสัมพันธ์ระหว่างข้อมูล รวมถึงเนื้อหาเกี่ยวกับภาษา SQL และการออกแบบฐานข้อมูล
[Normal] ในการพัฒนาระบบ ผู้วิจัยได้นำเทคโนโลยีปัญญาประดิษฐ์และการประมวลผลภาษาธรรมชาติมาใช้ในการประมวลผลคำถามของผู้ใช้งาน โดยใช้ Claude API เป็นส่วนหนึ่งในการสร้างคำตอบของระบบ และพัฒนา Chatbot ให้อยู่ในรูปแบบเว็บไซต์ ผู้ใช้งานสามารถป้อนคำถามเกี่ยวกับเนื้อหาที่กำหนดไว้ จากนั้นระบบจะประมวลผลและสร้างคำตอบที่เกี่ยวข้อง นอกจากนี้ยังมีการกำหนดขอบเขตเนื้อหา เพื่อให้ระบบสามารถแยกแยะคำถามที่อยู่ในขอบเขตและนอกขอบเขตของเนื้อหาได้
[Normal] จากการดำเนินการพัฒนาและทดสอบระบบ พบว่า Chatbot สามารถนำมาใช้เป็นเครื่องมือสนับสนุนการเรียนรู้เกี่ยวกับระบบฐานข้อมูลและภาษา SQL ได้ โดยสามารถรับคำถามและประมวลผลเพื่อสร้างคำตอบตามขอบเขตเนื้อหาที่กำหนด และสามารถนำผลการทดสอบมาวิเคราะห์ด้วย Confusion Matrix เพื่อประเมินประสิทธิภาพของระบบ ทั้งนี้ ผลการทดสอบยังสามารถนำไปใช้เป็นข้อมูลสำหรับปรับปรุงฐานความรู้และการทำงานของ Chatbot ให้มีความเหมาะสมต่อการใช้งานด้านการเรียนรู้มากยิ่งขึ้น
[Heading 3] ผลการประเมินประสิทธิภาพของ Chatbot
[Normal] การประเมินประสิทธิภาพของ Chatbot ใช้ข้อมูลคำถามจากเนื้อหาจำนวน 12 บท โดยมีผู้ประเมินจำนวน 6 คน รวมรายการประเมินทั้งสิ้น 660 รายการ
[Normal] ผลการประเมินด้วย Evaluation Matrix พบว่า
[Normal] True Positive (TP) จำนวน 378 รายการ
[Normal] True Negative (TN) จำนวน 138 รายการ
[Normal] False Positive (FP) จำนวน 75 รายการ
[Normal] False Negative (FN) จำนวน 69 รายการ
[Normal] เมื่อนำข้อมูลดังกล่าวมาคำนวณค่าความถูกต้องของระบบด้วยสูตร Accuracy Rate
[Normal] Accuracy = (TP + TN) / (TP + TN + FP + FN) × 100
[Normal] ได้ผลดังนี้
[Normal]                         Accuracy = (378 + 138) / 660 × 100

[Normal] ดังนั้น จากการประเมินข้อมูลทั้งหมด Chatbot ที่พัฒนาขึ้นมีค่าความถูกต้องโดยรวม ร้อยละ 78.18
[Normal] ผลการประเมินดังกล่าวแสดงให้เห็นว่า Chatbot สามารถจำแนกและตอบสนองต่อคำถามในชุดข้อมูลการทดสอบได้ถูกต้องในระดับหนึ่ง อย่างไรก็ตาม ยังพบรายการที่มีผลเป็น False Positive และ False Negative ซึ่งสามารถนำไปใช้เป็นข้อมูลสำหรับปรับปรุงระบบในระยะต่อไป
[Heading 3] ผลการประเมินจำแนกตามเนื้อหา
[Normal] จากการประเมิน Chatbot ครอบคลุมเนื้อหาจำนวน 12 บท โดยแต่ละบทมีจำนวนคำถามและผลการประเมินแตกต่างกัน ผลการประเมินพบว่าความถูกต้องของ Chatbot ในแต่ละบทมีความแตกต่างกัน
[Normal] เมื่อพิจารณาโดยภาพรวม พบว่าบางบทมีค่าความถูกต้องสูง ขณะที่บางบทมีค่าความถูกต้องต่ำกว่า ทั้งนี้ อาจเกี่ยวข้องกับลักษณะของเนื้อหา รูปแบบของคำถาม และความครอบคลุมของข้อมูลที่นำมาใช้ในการพัฒนา Chatbot
[Normal] ดังนั้น ผลการประเมินรายบทสามารถนำมาใช้เป็นข้อมูลสำหรับระบุหัวข้อที่ควรได้รับการปรับปรุงเพิ่มเติม โดยเฉพาะหัวข้อที่พบการจำแนกคำถามผิดหรือไม่สามารถตอบคำถามที่เกี่ยวข้องได้

[Normal] 1. การเตรียมและวิเคราะห์เนื้อหา
[Normal] เริ่มต้นจากการรวบรวมและวิเคราะห์เนื้อหาที่เกี่ยวข้องกับระบบฐานข้อมูลและภาษา SQL เพื่อนำมาใช้เป็นข้อมูลสำหรับพัฒนา Chatbot โดยเนื้อหาครอบคลุมหัวข้อสำคัญ เช่น คำสั่ง SQL ได้แก่ SELECT, WHERE, JOIN และ GROUP BY รวมถึงแนวคิดเกี่ยวกับระบบฐานข้อมูล เช่น ER-Diagram และ Normalization
[Normal]                ภาพที่ ก-1 แสดงการเตรียมเนื้อหาสำหรับใช้ในการพัฒนา Chatbot
[Normal] 2. การจัดเตรียมฐานความรู้
[Normal] นำเนื้อหาที่ผ่านการวิเคราะห์มาจัดหมวดหมู่และจัดเตรียมเป็นฐานความรู้สำหรับ Chatbot โดยกำหนดหัวข้อและเนื้อหาที่เกี่ยวข้องกับระบบฐานข้อมูลและภาษา SQL เพื่อให้ระบบสามารถนำข้อมูลไปใช้ในการตอบคำถามของผู้ใช้งานได้อย่างเหมาะสม
[Normal] ภาพที่ ก-2 แสดงการจัดเตรียมฐานความรู้สำหรับ Chatbot
[Normal] 3. การพัฒนา Chatbot
[Normal] นำฐานความรู้ที่จัดเตรียมไว้มาใช้ในการพัฒนา Chatbot โดยประยุกต์ใช้เทคโนโลยีปัญญาประดิษฐ์และการประมวลผลภาษาธรรมชาติ และใช้ Claude API เป็นส่วนหนึ่งในการประมวลผลคำถามและสร้างคำตอบของ Chatbot นอกจากนี้ แนวทางการพัฒนายังครอบคลุมการออกแบบคลังคำถาม–คำตอบและการกำหนดแนวทางในการประมวลผลข้อมูล
